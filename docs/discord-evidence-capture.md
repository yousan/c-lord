# Discord 実画面キャプチャ (dev/保守ツール, #243)

PR/Issue の証跡として **Discord クライアントの実際の見た目**のスクリーンショットを
AI 自身が取得するための内製ツール。テキストログでは表出しない問題
(レイアウト・ボタンの出/不出・リアクションランプ・添付の見え方) を
スクショとして残すことが目的 ([#287](https://github.com/yousan/c-lord/issues/287) P4)。

**これは c-lord 自身の開発・保守のためのツールであり、利用者に配る機能ではない。**
bot のランタイム (Cog / イベント / コマンド) には一切組み込まれていない。

## 仕組み — 役割分担

```
┌─ bot アプリ (c-lord / staging bot) ──────────────┐
│ REST API で読み取り (公認の自動化面)              │
│ メッセージ・スレッド・チャンネルの ID を特定      │
│ → https://discord.com/channels/<g>/<c>/<m> を構成 │
└──────────────┬───────────────────────────────────┘
               │ URL を渡すだけ
┌─ テストアカウント (使い捨て・通常アカウント) ────┐
│ 何もしない。ただログイン済みプロファイルが存在    │
│ Chrome が URL を開いて描画する (入力注入ゼロ)     │
└──────────────┬───────────────────────────────────┘
               │ OS レベルで撮影 (Discord から不可視)
┌─ Xvfb + ffmpeg x11grab ──────────────────────────┐
│ 仮想ディスプレイのフレームバッファ → PNG          │
└──────────────────────────────────────────────────┘
```

- **読み取り・特定 = bot** (bot アカウントの自動化は Discord が公認する面)
- **描画 = テストアカウントの素の公式クライアント** (アカウントは何の操作もしない)
- **撮影 = OS レベル** (クライアント改造なし・Discord から見えない)

## 規約面の整理 (#243 で確認済み)

Discord が禁じるのは (1) **ユーザーアカウントに自動でアクションさせること**
(self-bot) と (2) **クライアントの改造**。本ツールはどちらにも該当しない:

- アカウントは送信・リアクション・ナビゲート等のアクションを一切行わない。
  ナビゲーションは「ブラウザ起動時に URL を渡す」= 人がリンクを開くのと同じ
  クライアント操作で、ロード後の入力注入はしない
- 素の公式 Discord web をそのまま使う (改造なし)
- スクリーンキャプチャは OS の操作であり、アカウントのアクションではない

詳細な出典・判断材料は
[#243 の 2026-06-10 コメント](https://github.com/yousan/c-lord/issues/243)を参照。

### ⛔ 禁止事項 (規範。実装の説明ではない)

**モーダルの解除を含め、ロード後の入力注入は一切行わない。解除は人間が手で行う。**
キー送出 (`xdotool` / CDP `Input.dispatchKeyEvent` 等)・クリック・スクロール・
ナビゲーションのいずれも、読み込み済みのクライアントに対して行ってはいけない。

- **2026-08-26 の yousan 裁定**であり、利便性とのトレードオフを承知のうえで
  決めたもの ([#559](https://github.com/yousan/c-lord/issues/559) のコメント)。
  理由は Discord の規約を尊重するため。**「面倒だから自動化しよう」と
  蒸し返さないこと。**
- 実際に 2026-08-26、AI が CDP 経由で Escape を注入してモーダルを閉じた
  違反が起きている。**前例にしないこと。** その記録は #559 に残してある
- 代わりにやってよいのは「**撮れた PNG を見て、使えないと分かったら失敗にする**」
  こと (下記「撮れたかどうかの自動判定」)。画像検査は OS の操作の範囲に収まり、
  上の規約整理と矛盾しない

## セットアップ (人間が一度だけ)

1. **使い捨てのテスト専用アカウント**を Discord で新規作成する
   (捨てアドで可。本人の常用アカウントは使わない)
2. 撮影対象のサーバ (staging サーバ等) にそのアカウントを招待し、
   **閲覧 + メッセージ履歴**の読み取り権限だけ与える (送信権限も不要)
3. bot ホスト上で専用プロファイルにログインする (WSLg 環境なら
   ウィンドウが Windows デスクトップに出る):

   ```bash
   mkdir -p ~/.clord && chmod 700 ~/.clord
   google-chrome --user-data-dir=$HOME/.clord/discord-evidence-profile \
     "https://discord.com/login"
   ```

   テストアカウントでログインし、サーバが見えたらウィンドウを閉じる。
   セッショントークンがプロファイルに保存され、以降の撮影はすべて無人で動く。

## 使い方

```bash
# チャンネル/スレッド ID だけ渡す (推奨。guild はスクリプトが引く)
scripts/discord_evidence_shot.sh <channel_or_thread_id> -o evidence.png

# チャンネルの現在の画面
scripts/discord_evidence_shot.sh \
  "https://discord.com/channels/<guild_id>/<channel_id>" -o evidence.png

# 特定メッセージ周辺 (メッセージリンクを渡すとクライアントがそこへジャンプする)
scripts/discord_evidence_shot.sh \
  "https://discord.com/channels/<guild_id>/<channel_id>/<message_id>" -o evidence.png
```

URL は Discord 上でチャンネル/メッセージを右クリック → 「リンクをコピー」、
または bot の REST API で ID を特定して組み立てる。

**guild ID は手で書かない。** 別サーバの guild ID を書いても Discord は
エラーにせず**フレンド画面**を描くだけなので、「撮影アカウントの権限が無いのでは」
と誤診する事故が実際に起きた (#559)。ID だけ渡せばスクリプトが
`GET /channels/<id>` の `guild_id` を引いて URL を組む。フル URL を渡した場合も
guild が一致するか照合し、食い違えば正しい URL を示して**撮らずに終了**する。
照合には bot token が要る (`$DISCORD_BOT_TOKEN` → `$CLORD_ENV_FILE` →
リポジトリ直下の `.env` の順に探す)。無ければ照合はスキップし、その旨を表示する。

`--wait` の既定は **45 秒**。22 秒ではサイドバーがスケルトンのまま・本文が
真っ白の PNG が撮れる (#559 AC11)。

## 撮れたかどうかの自動判定 (#559)

**PNG が出来ていること = 撮れていること、ではない。** 次の 3 つはどれも
「正常な PNG だが証跡としては無価値」で、以前はすべて `captured:` と
成功表示されていた:

1. 販促モーダルに肝心の部分が覆われている
2. 描画途中 (サイドバーがスケルトン / 本文が真っ白) で撮れている
3. そもそも要求したチャンネルを開けていない (guild ID 取り違え・権限不足・
   セッション失効のログイン画面)

そこで `scripts/discord_evidence_shot.sh` は撮影後に
`scripts/evidence_qc.py` で**撮れた PNG を画像として検査**し、上記を検出したら
**`captured:` と言わずに非ゼロ終了**する (PNG は調査用に残す)。
判定は撮影済みファイルに対する画像処理だけで、クライアントには一切触れない。

```bash
python3 scripts/evidence_qc.py shot.png   # 0=使える / 2=証跡にならない / 3=Pillow 無しで検査不能
```

| code | 意味 | 対処 |
|------|------|------|
| `modal` | 背景が暗転し中央にカードがある | 人間に一度モーダルを閉じてもらう (下記) |
| `loading` | チャンネル一覧がスケルトンのまま | `--wait` を伸ばして撮り直す |
| `blank` | 本文領域に何も描かれていない | `--wait` を伸ばす / URL を見直す |
| `not-a-channel` | 画面下にメッセージ入力欄が無い | guild 取り違え・権限不足・セッション失効を疑う |

判定を外したい場合だけ `--no-qc` を付ける。その場合の表示は
`captured (UNVERIFIED — --no-qc was given):` で、**証跡としては使えない**。
Pillow が入っていない環境でも同様に `UNVERIFIED` と明示して続行する
(検査できていないことを黙らない)。

## 販促モーダルが出たとき — 人手は 1 回で全員分 (#559)

Discord の販促モーダル (「ショップ新着: プロフィールフレーム」「新着情報」等) は
テストアカウントの状態で出るもので、**ウィンドウサイズでは消せない**。
入力注入は禁止 (上記「禁止事項」) なので、**人間が一度手で閉じる**。

**プロファイル (`~/.clord/discord-evidence-profile`) は全スレッド共有**なので、
**その 1 回の解除で、以後のすべてのスレッド・すべての実行に効く。**
スレッドごとに人間へ依頼を飛ばさないこと (2026-08-26 に複数スレッドが同時に
同じ依頼を投げる事故が起きた)。

**人間が手で開くコマンド** (bot ホスト上。WSLg なら Windows デスクトップに出る):

```bash
DISPLAY=:0 google-chrome --user-data-dir=$HOME/.clord/discord-evidence-profile \
  "https://discord.com/channels/@me"
```

- **`DISPLAY=:0` が要る。** SSH セッションには `DISPLAY` が引き継がれないため、
  付けないと Chrome が起動しない (これで詰まった実績がある)
- 撮影スクリプトと同時に開けない (同一プロファイルで Chrome は 1 つ)。
  `pgrep -f discord-evidence-profile` が空なのを確認してから開く
- モーダルを閉じてウィンドウも閉じれば完了。以後の撮影は無人で通る

### 当面の緩和策: ウィンドウを縦に伸ばす (限界つき)

モーダルが出ている間、**唯一の緩和策**が `--size` を縦に大きく取ること
(例: `--size 900x2600`)。モーダルは画面中央に居座るが**高さが固定**なので、
ウィンドウを縦に伸ばした分だけ上下に地のメッセージがはみ出して写る。

Discord の実 CSS で確認した値 (2026-09-01 実測):

- モーダル本体は `max-height: 720px` (small) / `800px` (medium) の**固定 px**。
  ビューポート比ではないので、**縦に伸ばすほど帯の外に出る内容が増える**
- ただし `@media screen and (max-height:550px), screen and (max-width:485px)` で
  モーダルは全画面化する (`max-width:100%`)。つまり
  **幅を狭める / 高さを縮めるのは逆効果**
- サイズを変えても**モーダルが出なくなることはない** (出る/出ないはアカウント状態)

同じスレッドを 3 つの高さで実際に撮り、本文テキストの何割が中央 800px の帯の
外に出るかを数えた (2026-09-01):

| `--size` | 本文テキストの行 px | 帯の外 | 帯の外の割合 |
|----------|--------------------|--------|-------------|
| `900x900`   | 381  | 0   | **0%** |
| `1600x1500` | 652  | 219 | 34% |
| `900x2600`  | 1345 | 887 | **66%** |

つまり**既定サイズ付近では緩和策として機能しない** — 縦 2600px まで伸ばして
やっと本文の 2/3 が帯の外に出る。

**限界**: 帯の外に出た中に**撮りたいメッセージが来るかは運任せ**で、狙って
再現できない。周囲も暗転したままなので可読性も落ちる。読める証跡にならなければ
自動化で粘らず、上の手順で**人間に一度閉じてもらう**
(#492 PR #494 で発見、#559 で実測して位置づけを整理)。

## 証跡の置き場の規約 (#390)

**原則: 証跡 PNG は git ツリーに commit しない。GitHub Release アセットに
アップロードして URL を参照する。** バイナリを source repo に貯めると履歴が
不可逆に膨らむため。業界一般でも「使い捨てスクショは off-repo に置き PR には
リンクを載せる」が定石 (visual regression の Percy / Chromatic / Argos も
画像は自前ストレージ + PR にリンク)。GitHub にアップロードされた画像は
期限切れしない。

- **アップロード**: `scripts/evidence_upload.py` を使う。

  ```bash
  # 撮る → 上げる
  scripts/discord_evidence_shot.sh "<thread URL>" -o red.png
  scripts/discord_evidence_shot.sh "<thread URL>" -o green.png
  scripts/evidence_upload.py red.png green.png --issue 390
  # → 各 browser_download_url と貼り付け用 markdown が stdout に出るので
  #    その URL / ![...](url) を PR・Issue 本文に貼る
  ```

  画像は専用の **prerelease タグ `evidence`** にアセットとして載る
  (`https://github.com/<owner>/<repo>/releases/download/evidence/<name>`)。
  prerelease なので `releases/latest` には出ず、auto-upgrade を妨げない。

- **証跡は催促される前に貼る (必須)**。「言われたら付ける」ではなく、挙動/UI を
  変える PR・Issue には最初から RED / GREEN (前/後) の両方を貼る。
  **`dod-gate` CI は、免除ラベル (`no-runtime-change` / `documentation`) の無い PR の
  本文に証跡画像 (`![...](URL)`) も Release アセット URL も無ければ落とす (#391)。**
- **やってはいけない**:
  - PNG を `docs/evidence/<issue番号>/` 等に commit する (旧規約。既存の
    commit 済み PNG は過去 PR のリンク保全のため残すが、新規は作らない)。
  - **Discord CDN の添付 URL (`cdn.discordapp.com/attachments/...`) を
    本文に直貼りする** — 2024 年以降は期限付き署名 URL で数日で 404 になる。
    Discord 由来の画像は一度ローカルに落として上の script で上げ直すこと。
- **bot から user-attachments CDN は使えない**: ドラッグ&ドロップで付く
  `github.com/user-attachments/...` への自動アップロードは公式 API が無く
  (Web UI はブラウザ Cookie 必須)、headless な bot からは扱えない。だから
  Release アセットを使う。
- **yousan 提供のスクショ**は Issue にそのまま添付で良い (GitHub に上がった
  画像は期限なし)。

## 制約

- 撮れるのは**テストアカウントが参加しているサーバ/チャンネルだけ**。
  新しいサーバを撮影対象にするには人間が一度招待する
- 撮れるのは「リンク位置周辺のビューポート 1 画面」。長い流れは
  メッセージリンクを変えて複数枚撮る (スクロール注入はしない)
- セッションはいつか失効する。失効するとログイン画面が写るが、これは
  `evidence_qc.py` が `not-a-channel` として弾く
  → 人間がセットアップ手順 3 を再実行する (数ヶ月に一度程度の想定)
- 同一プロファイルで Chrome は 1 つしか起動できない。スクリプトが
  使用中チェックで直列化する
- Discord の販促モーダル(「ショップ新着」等)がテストアカウントに出ることがある。
  入力注入は禁止なので**閉じるボタンを自動では押せない** —
  [販促モーダルが出たとき](#販促モーダルが出たとき--人手は-1-回で全員分-559)を参照
  (検出は自動、解除は人間が 1 回)。

## セキュリティ

- プロファイル (`~/.clord/discord-evidence-profile`) には**テストアカウントの
  セッショントークン**が入っている。漏れたらそのアカウントは乗っ取られ得る。
  だからこそ**使い捨て・最小権限・staging のみ参加**にして、漏洩時の損失を
  ゼロに設計する。**本人の常用アカウントでのログインは絶対にしない**
- スクリプトは URL を `discord.com/channels/` に制限している。
  ログイン済みブラウザを任意サイトに向ける汎用ツールとして使えないようにするため
- パスワードはどこにも保存しない (ログイン時に人間が手入力するだけ)
