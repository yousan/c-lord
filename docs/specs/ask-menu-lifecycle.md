# あるべき動き: 質問メニューの一生（出てから消えるまで）

> 対象: Claude の `AskUserQuestion` / プラン承認がスレッドに出す **❓ ボタン付きメニュー**。
> 関連: [stop-button.md](./stop-button.md)（同じ「前のプロセスが残した UI」の話）/
> [`docs/askuserquestion-bridge.md`](../askuserquestion-bridge.md)（仕組みの詳細）。

## これは何か

Claude が tmux ペインの中で選択メニューを描いて**止まっている**とき、その選択肢を Discord のボタンとして出し、押された選択をペインへキーストロークとして送り返す仕組み。

**押せるボタンが1つでも嘘をつくと、そのセッションは永久に止まる。** Stop ボタンが死んでも「止められない」だけだが、質問メニューが死ぬと**答える手段そのものが無くなり**、質問を出した Claude はペインの中で待ち続ける。だから以下は「あったら親切」ではなく、この機能の成立条件。

## あるべき動き（利用者から見て）

### 出るとき

- スレッドに1つの質問につき **1つのメニュー**が出る。同じ質問が2枚出ることはない
- メニューを出す経路は4つある（ターン中 / ターン終了後の拾い直し / bot のターン外 / 60秒ごとの watchdog）が、**利用者から見た結果は同じ1枚**。どの経路で出たかによって、この先の挙動が変わってはいけない
- **質問の直前の説明（経緯・推し）が、メニューの1つ上に出る**（#399/#549）。経緯の無い質問は「藪から棒に聞かれた」ようにしか見えず、判断できない

### 未回答のあいだの見え方 ← #686

メニューが開いているあいだ、**CLI は jsonl に1文字も書かない**（回答されるまで丸ごとバッファする）。だから上の経緯は**ペインの描画結果**からしか取れない — 罫線で描かれた表・端末幅での強制改行・markdown の剥がれた本文。Discord は等幅で描かないので、**罫線の表はそのまま貼っても読めない**。

- **罫線文字が100個以上あるときは、その壁をそのまま貼らない。** 1通の**畳んだメッセージ**に置き換える: 何についての説明か（罫線の無い行）＋畳んだ量＋「回答すると、全文が読める形でここに届きます」
- **100個未満ならこれまでどおりそのまま出る。** 2〜3行の小さな表はテキストでも読めるので、見え方を変えない
- 畳むのは**見せ方だけ**で、本文が失われることはない。畳んだメッセージは下の「押したとき」で読める markdown に差し替わり、差し替えが入らなかったときは markdown が別メッセージとして届く（**畳んだ先が空、にはならない**）

**なぜ畳むのか**: 2026-09-08、1,900文字・罫線933個の説明が、その質問が未回答のまま**3日間**スレッドに貼りついていた。差し替え（#698）は回答後にしか来ないので、**読んで判断しないといけないあいだだけずっと読めない**という一番困る形になっていた。罫線を markdown の表に復元する案は、目的に対して重いとして採らなかった（裁定 2026-09-14）。

### 押したとき

- 押すと ⏳ 送信中 になり、キーがペインに送られ、**Claude の transcript で確認が取れてから** ✅ になる。「送った」と「届いた」は別物として扱う（#651）
- 複数選択は、選んだ項目が**メッセージ自体に残る**（プルダウンに ✅ が付いたまま見える）。「✅ 確定」を押すまで送信されない（#672）
- 押されたことは**必ずログに残る**。無音で失敗しない（#585）
- **回答すると、上の経緯が CLI 自身の markdown に差し替わる**（#698/#686）。畳んだメッセージも、ペインの描画そのままのメッセージも、**同じメッセージが書き換わる**だけで新しいメッセージは増えない。表が `table_*.png` になるのもこのタイミング（罫線の描画には表が無いので、それまでは付けようがない）

### 閉じるとき

メニューが答えを受け付けなくなる出口は5つ（時間切れ / 端末で回答 / 別コピーで解決 / 新しい指示で割り込み / Discord で回答）。**どの出口でもボタンは消え、なぜ閉じたのかが残る。** あとから押した人は「すでに回答済みです」「端末で回答されました」のように**本当の理由**を見る（「bot が再起動しました」を、再起動していないのに言わない — #536）。

### bot を再起動したとき ← #671

**再起動してもペインのメニューは開いたままで、Claude はそこで待っている。** 死ぬのはボタンの handler を持っていた Python オブジェクトだけ。だから:

- **再起動をまたいでも、出ているボタンは押せる。** 押して「アプリケーションは時間内に応答しませんでした」（Discord の3秒 ACK タイムアウト）になってはいけない
- **押したら答えが本当に Claude に届く。** 新しいプロセスがペインを読み直し、**まだ同じ質問が出ていることを確認してから**キーを送る
  - 確認は #633 と同じメニュー指紋（ヘッダ・質問文・選択肢の並び）で行う
  - 端末で回答済み／別の質問に変わっていた場合は**送らない**。「すでに閉じられています」「別の質問に変わっています」と理由を出す。開いているメニューなら何でも良いとして送ると、**違う質問にこの答えを入れてしまう**
- **メニューを出し直さない。** 再起動のたびに同じ質問がもう1枚増えるのは #633（3日で6枚、188回の再ブリッジ）で潰した挙動。復元は**すでに画面にあるメッセージ**に対してだけ行う
- **ペインがもう そのメニューを出していないメッセージは、起動時にボタンを外す。** 押せるように見えて押しても断られるだけの状態を残さない（⏹ Stop ボタンと同じ規律 — #634）
- 復元したことも、押した結果も**ログに残る**

### 起動時の後片付けは1箇所に集まっている

前のプロセスが残した UI の掃除は、**⏹ Stop ボタン（#634）も質問メニュー（#671）も同じ入口**（`c_lord/startup_recovery.py`）から走る。

これは整理の趣味ではなく #671 の再発防止そのもの: 掃除が2つの `on_ready` に分かれていたため、**片方（メニューの復元）は1度も動かないまま1か月以上気づかれなかった**。3種類目のゴミが出てきたら、ここに1行足す。新しい起動フックを増やさない。

## 仕組み（なぜそうできるか）

- `AskView` は persistent view（`timeout=None`、`custom_id` は `ask_{thread_id}_{q_idx}_{slot}` で固定）なので、**起動時に `bot.add_view()` で貼り直せば、すでに画面にあるボタンの routing が戻る**
- 貼り直すには質問の内容が要る。メニューを出した瞬間に `pending_asks` へ書き、閉じた瞬間に消す。**書き込みは投稿直後、削除は `_close()` の1箇所**（出口が5つあるので、他の場所に置くと必ずどれか1つが漏れる）
- 保存するのは「描くのに要るもの」だけでは足りない。**選択肢の並び順**（回答は `Down × index` で送るので、並びが変わると別の選択肢が選ばれる）、`allow_other`、`free_text_mode`（自由入力をどのキーで送るか — 間違えると #650 の「全部のキーが届いたのに『回答なし』」になる）まで含める

## 落とし穴（過去に踏んだもの）

| 症状 | 原因 | Issue |
|---|---|---|
| 再起動後にボタンを押すと赤字・ログ無音 | メニューを出す4経路すべてが `pending_asks` に書いていなかった。復元の仕組みは在ったが復元対象が常に0件 | #671 |
| 同じ質問が3日で6枚出る | 「出し直し」の台帳がプロセス内メモリにあり、再起動でリセットされていた | #633 |
| 「✅ 確定」を押しても無音 | 選択が View のインスタンス変数にしか無かった | #672 |
| キーは全部届いたのに「回答なし」 | 自由入力を、そのメニューに無い方の導線へ送っていた | #650 |
| 答えが届かないのに何も言わない | キー送信の失敗を握り潰していた | #600 |
| 再起動していないのに「bot が再起動しました」と出る | 閉じた理由を記録せず、全部を再起動のせいにしていた | #536 |
| 未回答の質問の上に、罫線だらけの1,900文字が3日間貼りついたまま | 経緯をペインの描画のまま貼っていた。読める markdown は質問が解決するまで来ないので、読む必要があるあいだは常に読めない | #686 |
