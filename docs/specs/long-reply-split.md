# あるべき動き: 長い返信の分割

> これは「あるべき動き」。理念 [`docs/PHILOSOPHY.md`](../PHILOSOPHY.md) の下位。迷ったら理念に照らす。

## これは何か

Discord の1メッセージには **2000文字** までしか入りません。
Claude の返信がこれを超えるとき、C-lord は返信を**複数のメッセージに分けて**Discord に届けます。
利用者から見れば、長い答えでも途中で切れず、全文がちゃんと読めるべき、というだけのことです。

なぜ要るか: C-lord はコーディングツールの入り口で、Claude はコードや長い説明をよく返します。
リモートで結果から判断する以上、その結果が欠けずに見えていないと判断できません（[理念 B](../PHILOSOPHY.md#b-リモートで結果から判断するには判断できる形で結果が見えないといけないa-の必須条件)）。
途中で切れた答えは「判断できる形で見える」を満たしません。

## あるべき動き（利用者から見て）

### 正常時

- **2000文字を超える返信でも、全文が届く。** 末尾が切れたり「…」で省略されたりしない。複数のメッセージに分かれて、続きとして読める。
- **分かれても1つの返信として読める。** 順番が入れ替わらない。前のメッセージの続きが次のメッセージにそのまま続く。
- **コードのまとまり（コードブロック）が壊れない。** 長いコードの途中で分割が起きても、各メッセージの中でコードブロックがきちんと閉じ、次のメッセージの頭で同じ言語のコードブロックを開き直す。だから、どのメッセージもコードはコードとして（等幅・色つきで）正しく表示される。
- **添付ファイルは最後のメッセージにだけ付く。** 分割しても添付が重複したり途中に紛れ込んだりしない。

### 境界

- **ちょうど2000文字** — 1メッセージに収まるので分割しない。各メッセージは必ず2000文字以下に収まる。
- **2000文字を1文字でも超えたら** — 分割する。どのメッセージも上限を超えない。
- **切れ目の選び方** — 読みやすいところで切る。まず段落の区切り（空行）、無ければ行の区切り、それも無ければ最後の手段として上限の位置で切る。いずれの場合もコードブロックは閉じ直して保つ。
- **コードブロックのちょうど真ん中で切らざるを得ないとき** — そこで閉じてから次のメッセージで開き直す。コードブロックの記号（バッククォート三連符）が片方だけ残って表示が崩れる、ということが起きない。

### エラー時

- **一部のメッセージ送信に失敗したとき** — 失敗をのみ込んで「全部送れた」ように見せない。利用者が「全文届いたつもりで一部欠けている」状態に置かれない。
- **分割処理でつまずいても、答えを丸ごと落とさない。** 最悪でも「切れて届く」より悪い「何も届かない」を避ける。

## バグの例（こうなっていたらバグ）

- **2000文字を超えた返信の末尾が切れる／「…」で省略される。** 全文が見えないのは誤り。これは #235 で実際に起きた症状（最終返答が途中で切れていた）。
- **コードブロックが途中で分割され、片側だけ記号が残って表示が崩れる。** コードの後半が等幅で表示されず、ただの折り返しテキストに見える、は誤り。閉じて開き直すべき（DESIGN_DECISIONS の決定 #5）。
- **分割した結果、順番が入れ替わる／一部が抜ける。** 続きとして読めないのは誤り。

## 根拠

- #235 — 2000文字を超える最終返答が途中で切れる不具合の記録（返信を届ける経路に分割処理が無かった）。
- #239 — それを直した PR。返信を改行の区切りで分け、各メッセージ内でコードブロックを閉じ直す処理を入れた。
- [`docs/DESIGN_DECISIONS.md`](../DESIGN_DECISIONS.md) の決定 #5「Fence-Aware Message Chunking」 — コードブロックの中では絶対に切らない／切らざるを得なければ閉じて次で開き直す、という設計判断。
- 理念 [B（結果が判断できる形で見える）](../PHILOSOPHY.md#b-リモートで結果から判断するには判断できる形で結果が見えないといけないa-の必須条件) — 欠けた結果では判断できない。全文が見えることが前提。
