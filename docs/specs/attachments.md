# あるべき動き: 添付ファイル

> これは「あるべき動き」。理念 [`docs/PHILOSOPHY.md`](../PHILOSOPHY.md) の下位。迷ったら理念に照らす。

## これは何か

Discord のメッセージにファイルを付けて送ったとき、それが Claude にどう渡るか、という話です。

利用者が「ファイルを添付した」と言うとき期待しているのは、**Claude がそのファイルを開ける**ことです。
本文に貼り付けた文字列ではなく、ファイルとして渡っていてほしい。

## あるべき動き（利用者から見て）

### 正常時

- **添付したファイルは、Claude が開けるファイルとして渡る。** 「このファイルを読んで」と言えば読める。
- **サイズで挙動が変わらない。** 数バイトでも数 MB でも、同じように渡る。
- **種類で挙動が変わらない。** テキストでも画像でも PDF でも、同じように「ファイル」として渡る。
- **添付は利用者のリポジトリを汚さない。** Claude がコミットしても添付ファイルが混ざらない。
- **同じ名前のファイルを2つ添付しても、両方渡る。** 片方が消えたり上書きされたりしない。

### 境界

- **1メッセージあたりの個数** — 10 個まで。超えた分は**渡さないが、渡さなかったと告げる**。
- **1ファイルのサイズ** — Discord 自体の上限（最大 100MB）まで。それを超えるものは渡さないが、やはり**告げる**。
- **リポジトリが紐づいていないスレッド** — 保存先が無いので渡せない。これも**告げる**。
- **同名ファイル** — 2つ目は `name-2.ext` として並べて置く。
- **危険な名前**（`../../etc/passwd`、`/etc/shadow`、`.bashrc` など）— ファイル名だけを取り出して無害化し、
  必ず添付用ディレクトリの中に収める。ワークスペースの外には絶対に書かない。

### エラー時

- **渡せなかった添付は、必ずスレッドに名前と理由が出る。** 「⚠️ 次の添付は Claude に渡せませんでした:
  `foo.bin` — 120.0 MB は上限 100.0 MB を超えています」のように、**どのファイルが・なぜ**渡らなかったかが分かる。
- **黙って捨てない。** これが一番やってはいけないこと。利用者から見ると「添付したのに Claude がファイルは無いと言う」
  という、原因の分からない壊れ方になる。
- **1つ失敗しても他は渡る。** ダウンロードに失敗した添付があっても、他の添付は普通に渡る。

## バグの例

- 60KB の `.md` を添付したら何の表示も無く、Claude が「そのようなファイルはありません」と答える（#528 以前の実際の挙動。
  上限 50KB を超えた添付を `logger.debug` だけ出して捨てていた）
- 添付の中身がプロンプトに展開され、長いと入力そのものが tmux の上限を超えて消える（#527）
- 画像の添付が期限付き CDN URL でしか渡らず、1通目だけ URL が壊れて取得に失敗する（#529）
- 添付ファイルが `git status` に出てきて、Claude の `git add -A` でコミットに混ざる

## 根拠

- #528 — 無言ドロップの廃止と、インライン展開からディスク保存への転換。
- #527 — インライン展開が tmux の入力上限を超えさせていた（[[input-delivery]] 参照: `input-delivery.md`）。
- 理念: 入口で入力が消えることは「リモートで結果から判断する」の前提を壊す。
