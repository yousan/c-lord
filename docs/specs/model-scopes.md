# `/model` — セッション・チャンネル・全体の model / effort (#918)

## 目的

全体設定を一時的に書き換えて、個別の作業のモデルを選ぶ運用をやめる。Discord の `/model` から、
**セッション（= スレッド）・チャンネル・この C-lord インスタンス全体**の model と effort を、
それぞれ独立に設定・確認できるようにする。

## 解決の順序（model と effort は別々に解決する）

セッションで明示した値 > チャンネルで明示した値 > グローバル > 起動時に読み込んだ環境設定（`.env` を含む）

- グローバルは**この C-lord インスタンスの中だけ**。別インスタンスには波及しない。
- セッションを作るとき、**実効値と「どの階層から来たか」を保存**する。上位の設定を変えても、
  `include-existing` を付けない限り既存セッションの保存値は変わらない。
- 「セッションで明示指定した値」と「継承して保存しただけの値」は区別する。保護されるのは前者だけ。

## コマンド

| 入力 | 効果 |
|---|---|
| スレッド内 `/model sonnet` | そのセッションの model だけ変更 |
| チャンネル直下 `/model sonnet` | そのチャンネルの**新規セッション用**だけ変更 |
| `/model sonnet effort:medium` | 同じ範囲で両方変更 |
| `/model effort:medium` | effort だけ変更（model は維持） |
| `scope:session\|channel\|global` | 対象を明示。スレッド内の `scope:channel` は親チャンネル |
| `include-existing:true` | channel / global の変更を、終了していない既存セッションにも反映（既定 false） |
| `/model inherit` / `/model effort:inherit` | その範囲の指定を解除（もう一方は維持）。セッション・チャンネル・全体のどこでも使える |
| 値なし `/model`、`/model scope:global` など | **表示のみ** |

意味が成立しない指定（チャンネル直下の `scope:session`、`session` と `include-existing` の組み合わせ、
値のない `include-existing`、不正な scope / モデル / effort、effort に対応しないモデル＋effort）は
**説明付きのエラーにして、何も変更しない**（部分適用なし）。

旧 `/model show` `/model set` は無くなった（Discord は同名のグループとコマンドを両立できない）。
テキストの `!model-show` `!model-set` は従来どおり動く。`!model-set` はグローバルの model を変える。

## 既存セッションへの反映（`include-existing:true`）

- 対象は終了していないセッション（待機中・スリープ中を含む）。**停止済みは対象外**。
- **実行中のターンは止めない・切り替えない。** 次のターンから変わる。
- 項目（model / effort）ごとに保護する:
  - セッション自身が明示した項目は、channel / global どちらの変更でも保護される。
  - global の変更では、**チャンネルが明示した項目**も保護される。
  - 例: セッションが model だけ明示していれば、effort は上位から反映される。
- 例外設定まで消す強制一括上書きは対象外。
- `inherit` は解除した項目について**現在の**上位設定を採用する。セッションでの解除は次のターンから。
  channel / global での解除は、通常の既存維持ルールと `include-existing` に従う。

## ターン開始時の確定と Claude の切り替え

- ターンの開始時に model と effort を**ひとつの組として**確定する（単一のトランザクション）。
  設定変更と競合しても、実行中の組が「新旧の混在」になることはない。
- Claude Code が起動している組（`applied`）と次のターンの組が違うときだけ、Claude を
  `--resume` + 新しい `--model` / `--effort` で**立て直す**（会話は引き継ぐ。スレッドに
  `🔄 モデル設定が変わったため…` の1行が出る）。違わなければ何もしない。
- **ペインに `/model` `/effort` を打ち込む方法は取らない。** Claude Code のそれは選択を
  ユーザー設定ファイルに「既定として保存」するため、ホスト上の他の Claude すべてのモデルが変わってしまう。
  コマンドラインの `--model` / `--effort` は保存されない。
- スケジュール実行・webhook 起動のスレッドも同じ解決を通る。**bot の再起動直後（チャットのターンや `/model` がまだ一度も走っていない間）も同じ**（#954 — 以前はこの間だけ起動設定のモデルで動いていた）。`/skill` が Claude を新規に
  起動する経路は従来どおりインスタンスの起動設定を使う（未対応）。

## 表示

```text
             model   effort
セッション   —       —       ← スレッド内のみ
チャンネル   sonnet   —
グローバル   opus     medium
.env         opus     high

新規に適用 → sonnet / medium
設定元     → チャンネル / グローバル
```

- チャンネル直下: そのチャンネルの新規用の実効値と設定元。全セッションの列挙はしない。
- スレッド内: そのセッションの**保存した**実効値と設定元（今の上位設定で再解決した値のようには見せない）。
  実行中の組と次のターンの組が違うときだけ `実行中 → … （次のターンから …）` を追記する。
- `.env` 行は**起動時に読み込んだ値**で、ディスク上の未適用の編集は反映しない。値が環境変数や
  組み込み既定から来ているときは、その出所を `※ .env 行の出所: …` に書く。秘密値・設定ファイルの全文は出さない。
- 変更結果は項目ごとに「新規のみ」「既存へ N 件反映」「個別指定のため M 件維持（セッション／チャンネル）」を返す。

## 権限

引数なしの表示は誰でも。**変更は従来の `/model set` と同じ許可リスト**（`Authorizer`）を通り、
権限がなければ何も変えずに拒否する（#781）。

## 保存先（再起動後も残る）

`channel_model_settings`、`session_model_settings`（明示値・保存した実効値と由来・起動した組・次ターン適用予定）、
グローバルは従来の `settings` の `claude_model` と新設の `claude_effort`。
