# あるべき動き: サブエージェントの作業をスレッドに残す

> これは「あるべき動き」。理念 [`docs/PHILOSOPHY.md`](../PHILOSOPHY.md) の下位。迷ったら理念に照らす。

決定の経緯は #969（調査と案）→ #971（実装）。#970 も同じ変更で直した。

## なぜこれがあるか

スレッドの中で Claude にサブエージェントで手分けさせると、claude のプロセスを増やさずに済む（1本あたり約 285MB。サブエージェントは同じプロセスの中で動くので +45MB ほど）。ところが c-lord は、Claude Code がサブエージェントの会話を書く別のファイル（`<session>/subagents/agent-<id>.jsonl`）を読んでいなかった。そのため Discord に残るのは、親 Claude が自分の言葉で書いた1文だけだった（4〜5KB の報告が140字ほどになる）。親のターンの途中で終わった子は、終わったことすら残らなかった（#969 の実測）。

C-lord を使う理由の1つは「Discord に全部の記録が残ること」（理念の B）。手分けするほど記録が欠けるのでは、手分けを勧められない。

## あるべき動き

### 既定（何も設定しない）

サブエージェントが1回走るごとに、スレッドに2行出る:

```
-# 🤖 サブエージェント「Review PRs: mirror group」開始        ← 走っている間、添付が差し替わる
  …
-# 🤖 サブエージェント「Review PRs: mirror group」終了 · 6:12 · ツール 48 件   📎 subagent-1-Review-PRs-mirror-group.md
```

- **開始の1行**には、子が走っている間、途中経過のファイルが付いて、変化があれば `CLORD_SUBAGENT_PROGRESS_SECONDS`（既定60秒、最小10秒）ごとに差し替わる。行の文言も `作業中 · 3:12 · ツール 12 件` に変わる。終わると `開始（終了は下）` になり、添付は外れる
- **終了の1行**には `subagent-<番号>[-<名前>].md` が付く（番号は子が出てきた順。名前は ASCII の部分だけ）。中身は、最終報告の全文、親からの依頼、途中のツール呼び出し・結果・子の発言・受け取った連絡（`📨`）・送った連絡（`✉️`）
- 子が再開された（親や別の子に `SendMessage` で話しかけられた）ときは、`再開` の1行から同じことを繰り返す。**1回の走りごとに、開始・終了がちょうど1回ずつ**
- 名前は Agent の `description`、Agent Teams の in-process teammate なら name（行の頭は `チームメイト「bob」`）
- ターンの途中で終わった子（親のターンに取り込まれた通知）も、同じように終了の1行が出る
- **フォアグラウンドの Agent 呼び出し**（`run_in_background: false` を明示したとき）には終わりの通知が来ない。親の記録に入るその呼び出しの結果（`tool_result` の `toolUseResult` に agentId と `status`）を終わりとして、その場で1回閉じる（#1027）。`run_in_background` を省いた呼び出しは、対話モードでも `-p` でもバックグラウンドで走り、通知が来る（CLI 2.1.312 で実測、下の表）
- 終わりの通知が来なくても、子のファイルが30秒止まっていて `meta.json` が `finished` で、**子の最後の行が発言の終わり（`stop_reason: end_turn`）なら**終了として閉じる。`finished` は前の走りのものが残ったまま再開されることがあり、それだけで閉じると、再開した子が長い Bash の間に「終了」になっていた（#1027）。30分止まったままなら `終了（記録が止まりました）` で閉じる（Claude ごと落ちた子が「作業中」のまま残らないように）
- 投稿にも添付にも、agentId・`/tmp/claude-…` の内部パス・Claude 向けの内部指示文は出さない（agentId は子の名前に置き換える）
- bot を再起動しても、再起動の前に出したものは出し直さない。**再起動の時点でファイルにあった分は読まない**（再起動をまたいで走っていた子は、続きから `再開` として出る）。再起動の瞬間に子が1行を書きかけていたら、その行は書き終わってから1件として読む（#1026 — 行の途中から読み始めて、依頼や最終報告を落としていた）。
- **再起動をまたいだ走りの、前の開始の1行は「作業中」のまま残さない**（#1027）。走っている子の開始の1行は `<project_dir>/.clord-subagent-runs.json` に書いておき、次に起動したとき `開始（記録が途切れました — c-lord の再起動など）` に書き換える。子がまだ走っていれば、続きは新しい `再開` の1行と終了の1行で1組になる。`.clord-session` の無い古いスレッドでは、親の記録で初めてセッションが分かった時点のファイルを基準にする

`CLORD_SUBAGENT_LOG=0` で、この全部を止められる。

### 重い作業でも bot を止めない（#1025）

添付づくり（本文の組み立て・agentId の置き換え・一時ファイルへの書き込み）と、子のファイルの一覧（`glob`）は、イベントループではなくワーカースレッドで行う（#537 の決まり — ループが止まると Discord の heartbeat が遅れて再接続になり、その間のメッセージを取りこぼす）。置き換えは 1 MB に切ったあとの本文にだけかける。子の途中経過は、メモリには最初の 1/5 と最新の分だけを持つ（合わせて約 100 万字。間で捨てた行数は添付に `…（途中の N 行は大きすぎるため省略）…` と出る）。

### `CLORD_SUBAGENT_VOICES=1` のとき（やり取りと最終報告を名前付きで出す）

上に加えて、**話した側の名前で**次がスレッドに出る:

| 何 | 名前 | 本文 |
|---|---|---|
| 親から子への依頼（Agent の prompt） | 親 | `→ **alice**（依頼）` ＋ 依頼の全文 |
| `SendMessage` での連絡（子→子・子→親・親→子） | 送った側 | `→ **bob**` ＋ 本文 |
| 子の最終報告 | 子 | `📝 **最終報告**` ＋ 報告の全文 |

- 連絡は**送った側の記録だけ**から出す（受けた側の記録は同じ連絡なので出さない）。だから1つの連絡は1回だけ出る
- 長いものは 2000 字ごとに分けて出し、5400 字を超える分は `…（続きは添付）` で切る（全文は添付にある）
- **途中のツール操作はスレッドに出さない**（添付にだけある）
- 名前の出し方: bot に **Manage Webhooks** があれば、親チャンネルに `c-lord subagents` という webhook を1つ作り（あれば使い回す）、投稿ごとに username を変える。無ければ bot の投稿として、本文の先頭に `**alice**` を付ける。**webhook は「あれば使う」で、必須の権限は増やさない**
- 人が Discord から子に話しかける機能は**まだ無い**（宛て方は使ってから決める — #971）

### c-lord が自分の声を命令として拾わないこと

c-lord は、スレッド内の webhook の投稿を Claude への依頼として扱う（Claude から Claude に発注する経路）。そのままでは、子の名前で投稿した連絡が、そのまま親への新しい依頼になってしまう。だから:

- `c-lord subagents` の webhook の id は、**最初に投稿する前に** `~/.c-lord/voice-webhooks.json` に記録する（同じホストのインスタンス全部で共有）。記録はファイルをロックして読み直し、足してから書く。知らない id の webhook の投稿が来たら、ファイルを読み直してから判定する（#1024 — 以前は起動時に1回だけ読み、自分の覚えている分で上書きしていたので、本番と staging が互いの id を消し合っていた）
- その webhook の投稿は、新しいターンを始めない・拒否の DM を出さない・再起動後の取りこぼしの拾い直し（#745/#776）で依頼として扱わない・テキストコマンドとして動かない

### サブエージェントの表示が壊れても、返事は止まらない

この表示は付け足しの機能です。読み取りで何が起きても（想定外の形の行など）、ログに残して先へ進み、
**スレッドの返事の転送（transcript ミラー）は止めません**（#1021）。

## どこから読んでいるか（CLI 2.1.312 で実測）

| 知りたいこと | 読むところ |
|---|---|
| 子の会話 | `<project_dir>/<session-id>/subagents/agent-<id>.jsonl` |
| 子の名前 | 同じ場所の `agent-<id>.meta.json` の `name` / `description` |
| 走りの終わり | 親の jsonl の `queue-operation` `enqueue` に入る `<task-notification>`（`<task-id>` = agentId）。ターンに取り込まれても必ず書かれる。再開された子には2回目が来る |
| フォアグラウンドの走りの終わり | 親の jsonl の、その Agent 呼び出しへの `tool_result` の行の `toolUseResult`（`agentId`・`status: completed`）。meta は `requestShape: "foreground"`、通知は来ない。バックグラウンドの起動にも `toolUseResult` が付くが `isAsync: true`・`status: async_launched` で、終わりではない（2026-10-29 実測、`tests/fixtures/subagents/foreground/`） |
| teammate の終わり | 親の jsonl の `idle_notification` |
| 連絡 | 送った側の jsonl の `SendMessage` の tool_use（`to` = agentId / `main` / name） |

## 対象外

- Agent Teams の split pane（`--teammate-mode tmux`）。c-lord の窓の管理とぶつかるので使わない（#969）
- 人から子への話しかけ
- 進捗のターン中の行（`⚙️ 作業中`）に子のツール件数を足すこと
