# あるべき動き: コミットの Co-authored-by（誰が依頼したか）

> これは「あるべき動き」。理念 [`docs/PHILOSOPHY.md`](../PHILOSOPHY.md) の下位。迷ったら理念に照らす。

## これは何か

C-lord のスレッドで頼んだ作業を Claude がコミットすると、そのコミットに **「誰が依頼したか」と「AI が書いたこと」が Co-authored-by として残ります**。

```
feat: 長い返信を分割する

Co-authored-by: yousan <1234567890@users.noreply.discord.com>
Co-Authored-By: Claude <noreply@anthropic.com>
```

なぜ要るか: C-lord は「Discord から複数のセッションを回す」道具なので、**1台のホストの git identity にすべての人の作業が集まります**。
そのままだと `git log` の author は全部ホストの名前になり、**あとから「この変更は誰が言い出したのか」を履歴から辿れません**。
チームで使うほどこの情報は失われます。だから **依頼者を一次情報としてコミット本文に残します**。

メールアドレス欄は `<Discord のユーザーID>@users.noreply.discord.com` という Discord 由来の擬似アドレスです。
GitHub のアカウントとは結び付かないので GitHub 上でアバター付きにはなりませんが、**誰が依頼したかは ID で一意に辿れます**。

## あるべき動き

### 正常時

- スレッドで A さんが頼んだターンの中で作られたコミットには **A さんの Co-authored-by** が付く。
- 同じスレッドで次に B さんが頼んだら、そのターンのコミットには **B さんの Co-authored-by** が付く（スレッドを作った人ではなく、**そのターンを頼んだ人**）。
- あわせて **Claude の Co-authored-by** が付く。
- Claude が自分で `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>` のようなモデル名入りの署名を書いていたら、**そちらを残し、C-lord は重ねて足さない**（1コミットに Claude の行が2つ並ばない）。
- `git commit -m "..."` のように**エディタを開かないコミットでも付く**。コミットのやり方を利用者や Claude が変えても、付き方は変わらない。

### 境界

- **同じターンで何回コミットしても、`--amend` しても、行は増えない**（すでにある同じ相手は足さない）。
- **表示名に改行や `<` `>` が入っていても**、行が壊れたり別人の行が捏造されたりしない。表示名は1行に収まる形に整えてから使う。
- **表示名が空**（または記号だけ）の人は `discord-<ユーザーID>` という名前で記録される。
- **マージコミット**（`git merge`）には付けない。
- **人が起点でない実行**（スケジュール実行など）では、Discord の行は付かず **Claude の行だけ**になる。
- **CI/CD の webhook から起きたターン**は、その webhook の表示名が依頼者として残る（「何が起こしたか」の一次情報として妥当）。

### エラー時

- **コミットが失敗することは絶対にない。** 何らかの理由で Co-authored-by を付けられなくても、コミットはそのまま成功する（署名は履歴の付加情報であって、作業を止める理由にはならない）。
- 対象リポジトリに **C-lord 以外の `prepare-commit-msg` の仕掛けがすでにある**場合は、**それを壊さない**。この場合 Co-authored-by は付かず、ログに警告が出る。
- リポジトリ側が `core.hooksPath` で仕掛けの置き場所を変えていても、**その置き場所に対して正しく効く**。

### 止め方

既定は**有効**（設定なしで動く）。止めたいときは C-lord に `CLORD_COAUTHOR=0` を設定して再起動する。
止めると、既に置かれていた C-lord の仕掛けも次のターンで取り除かれ、以後のコミットには付かなくなる。

## バグの例

- スレッドで A さんが頼んだのに、**コミットに B さん**（スレッドを最初に作った人）の Co-authored-by が付いている。
- 1つのコミットに **Claude の Co-authored-by が2行**並んでいる。
- `--amend` するたびに **同じ Co-authored-by が増えていく**。
- 表示名に改行を入れた利用者が頼むと、**身に覚えのない第三者の Co-authored-by** がコミットに現れる。
- Co-authored-by を付けられなかったせいで **`git commit` 自体が失敗する**。
- 利用者のリポジトリにあった husky などの `prepare-commit-msg` が **勝手に上書きされて消える**。

## 根拠

- Issue [#518](https://github.com/yousan/c-lord/issues/518) — 起票と決定事項（フック方式 / Discord 擬似メール / そのターンの依頼者のみ）。
- system prompt で Claude に「付けてね」と頼む方式は採らない。Claude が忘れると付かず、それは [#491](https://github.com/yousan/c-lord/issues/491)（Claude がターンを終えたのに投稿しない）と同じ失敗の形になるため。仕掛け（git hook）で機械的に保証する。
- 理念 [PHILOSOPHY.md](../PHILOSOPHY.md) — 「複数を並行して進める」道具である以上、**誰の依頼で生まれた変更かを後から辿れること**は履歴の最低限の責務。
