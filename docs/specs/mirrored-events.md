# あるべき動き: スレッドに流れるイベントの選別

> これは「あるべき動き」。理念 [`docs/PHILOSOPHY.md`](../PHILOSOPHY.md) の下位。迷ったら理念に照らす。

## これは何か

既定の jsonl モードでは、Claude Code が書く transcript を `TranscriptMirror` がスレッドへ流します。**そこには「利用者に見せるべきもの」と「見せるべきでないもの」が混ざっています。**

この spec は「**何を 👤（人間の入力）として出してよいか**」を定めます。

## 大原則

**👤 は「その人が実際に打ったもの」だけ。**

利用者から見て「自分が打っていないのに自分の発言として出ている」のは、何が起きているのか分からないうえに、内部の情報（ファイルパスなど）を晒します。ハーネスが内部的に user ロールへ注入する制御メッセージは、**人間の入力ではありません**。

## あるべき動き

### 👤 として流すもの

- 利用者が Discord で打ったメッセージ
- 利用者が tmux ペインで直接打ったメッセージ

### 👤 として流してはいけないもの

| 種類 | どう扱うか | 根拠 |
|---|---|---|
| c-lord 自身が送った入力のエコー（ZWSP 印つき） | **捨てる**（Discord には既に原文がある） | — |
| **開いている質問への文章回答のエコー（ZWSP 印なし）** | **捨てる**（同上。印が無くても c-lord 由来） | #682 |
| `<bash-input>` / `<bash-stdout>` / `<bash-stderr>` — ペインの `!` コマンド | **ツール活動**として扱う（progress.txt に畳む） | #487 |
| `<task-notification>` — バックグラウンドタスクの完了・停止通知 | **ツール活動**として扱う（progress.txt に畳む） | #380 |
| **compact の継続プロンプト** — 文脈圧縮の後にハーネスがセッションに撃ち込む要約 | **「🗜️ コンテキストを圧縮しました」の1行**に置き換える | #628 |
| `<command-name>` / `<command-message>` / `<command-args>` — ペインで打った `/compact` などの記録 | **ツール活動**として扱う（`🔧 /compact`） | #628 |
| `<local-command-stdout>` — そのスラッシュコマンドの出力 | **ツール活動**として扱う（ANSI を剥がす。空なら捨てる） | #628 |

### `<task-notification>` の扱い（#380）

出すのは **`<summary>` だけ**です。これがハーネスが人間向けに書いている唯一のフィールドです。

```
↳ ⏹ バックグラウンド: Background command "Final merge attempt for 539" completed (exit code 0)
```

- **`<task-id>` / `<tool-use-id>` / `<output-file>` は出さない。** 内部 ID であり、`<output-file>` は `/tmp/claude-…` の実パスそのもの（2026-08-27 実測で、漏れていた 17 件すべてがパスを露出していた）
- `<summary>` が無ければ `<status>`（`completed` / `killed` / `failed`）で代替する
- どちらも取れない・壊れているときは**タグを剥がす**。生の XML は絶対に Discord へ出さない
- 中身が空なら**何も出さない**（空の泡を作らない）

`tool_result` として扱うので、minimal モードでは progress.txt に畳まれ、**同時に [ターン中の進捗表示](./turn-progress.md) の「ツールが動いている」根拠にもなります**。つまり「バックグラウンドが動いている」ことは、1 通ずつメッセージを増やさなくてもターン中に見えます。

### compact の扱い（#628）

文脈が一杯になると、ハーネスは会話を圧縮し、**その要約を `user` ロールの文字列として
セッションに撃ち込んで**再開する。2026-08-29 03:38 JST の実例では **14,988 文字**で、
reply chunker がこれを **9 通**に割り、その全部が `👤` 付きだった。
＝「意味の分からない英語の長文が9通流れてきて、しかも自分が言ったことになっている。」

- 出すのは **1 行だけ**: `🗜️ コンテキストを圧縮しました`
- **黙って消さない。** 圧縮は「Claude が急に前の話を忘れたように見える」理由そのものなので、
  起きた事実は残す。残さないと、利用者は理由の分からない挙動だけを見ることになる
- ただし残すのは**事実だけ**で、ハーネスの本文は 1 文字も出さない
- 判定は**ハーネス自身のフラグ**で行う: `isCompactSummary` と
  `isVisibleInTranscriptOnly`（＝「CLI の transcript ビューにだけ出す」）。
  これは Discord に必要な判断とまったく同じ意味。英語の書き出しでの判定は
  **フラグが無い古い CLI 向けのフォールバック**に留める — 文言は変わりうるし、
  利用者がその文を引用することもある

### 印の無いエコーの扱い（#682）

**「c-lord が送ったか」の判定は ZWSP 印だけでは足りません。**

利用者が開いている質問に文章で答えると、その文は Discord から来たのに、
ペインには `send_literal` で**印を付けずに**打ち込まれます。印を付けないのは意図的で、
その文字列はメニューの自由入力欄に入ってそのまま**回答本文**になるため、
印を混ぜると回答そのものが汚れるからです（#172 / #650）。

しかし Discord から見れば、これはまぎれもなく c-lord 由来の入力です。印だけで判定していた頃は、
**利用者が書いた文が2秒後に bot の発言として 👤 付きで並んで**いました
（「送り直されたのか」「別の誰かが同じことを言ったのか」が分からない）。

- **印の代わりに「c-lord が打った本文」を控えて突き合わせる。**
  `send_literal` した文字列を記録し、印の無い `user` イベントが来たらそれと照合する
- **回答本文には一切手を入れない。** TUI に渡る文字列は従来どおり（#682 AC3）
- 照合は**完全一致**（空白と紛れ込んだ印を除いた形での一致）に限る。部分一致や曖昧一致にすると、
  回答を**引用しただけの人間の発言**まで飲み込む
- 一致は**1回限り**で消費し、時間が経てば失効する。取りこぼしたときの縮退は
  **「重複して出る」（今までどおり）であって、「消える」ではない**
- **人がペインで直接打った入力は引き続き 👤 で流す**（この経路を塞ぎすぎない）

### 境界

- **タグを含むだけの人間のメッセージは人間のメッセージ。** 判定は「その文字列で**始まる**か」で行う（`<task-notification>` について語っている文章を巻き込まない）
- **`<command-name>` は閉じタグまで揃っていることを要求する**（#628）。`<bash-input>` や
  `<task-notification>` と違って短く引用しやすい語なので、「`<command-name>` の話をしたい」は
  人間の発言。本物の記録は必ず閉じているので、これで取りこぼしは出ない
- ZWSP 印のついたエコーは、中身がタグであってもエコーとして捨てる（判定順に依存しない形で担保する）

### エラー時

- 未知の形のマーカーが来ても、**生のタグを Discord に出さない**ことを最後の砦とする

## バグの例

- 自分が打っていない `👤 <task-notification>…` がスレッドに出る → **バグ**（#380）
- `/tmp/claude-…` や `/home/…` の内部パスがスレッドに出る → **バグ**
- 生の `<bash-input>` や `<task-notification>` タグがそのまま出る → **バグ**（#487 / #380）
- バックグラウンドタスクの完了が**どこにも**残らない → **バグ**（progress.txt には残すべき）
- 人間が `<task-notification>` について書いた文章が 👤 で出ない → **バグ**
- compact のたびに英語の長文が 👤 で流れる → **バグ**（#628）
- 質問に文章で答えると、自分が書いた文が 👤 付きで再投稿される → **バグ**（#682）
- 人がペインで直接打った文が 👤 で出なくなる → **バグ**（#682 で塞ぎすぎた場合）
- 圧縮が起きたことが**どこにも**残らない → **バグ**（1 行は残すべき）

## 根拠

- **#628** — compact の継続プロンプトが 👤 で **9 通**流れる。#380 と同じクラスなのに片方だけ塞がれていた
- **#380** — `<task-notification>` が 👤 で流れる。2026-08-27 実測で本番 16 スレッド中 4 スレッド・17 件、**全件がパスを露出**
- **#682** — メニューへの文章回答が 👤 で再投稿される。#530 が塞いだ「スレッド1通目のエコー」と同じ穴の別経路で、
  `send_literal` が印を付けない（付けてはいけない）ことが原因
- **#487** — `<bash-*>` を同じ理由で弾いた前例。本 spec の型はここから
- **#539** — ツール活動として扱うことがターン中の進捗表示と噛み合う
- **#71 / #216 / #492** — jsonl mirror が既定の配信経路であること
