# あるべき動き: tmux のセッションとウィンドウの割り当て

> これは「あるべき動き」。理念 [`docs/PHILOSOPHY.md`](../PHILOSOPHY.md) の下位。迷ったら理念に照らす。

## これは何か

C-lord の各スレッドは、裏側では tmux のウィンドウの中で動いています。`tmux attach` すればその画面をそのまま覗けます。

このファイルは「**どのスレッドが、どの tmux セッションの、どのウィンドウに入るか**」を決めるものです。attach 先を探すときの地図になります。

## あるべき動き（利用者から見て）

### 正常時

- **tmux セッションは「リポジトリごと」にまとまる。** チャンネルごとではありません。
- **セッション名はリポジトリ名。** リポジトリの URL の末尾から作ります。
  - `https://github.com/yousan/c-lord.git` → `c-lord`
  - `git@github.com:yousan/NiyaReco.love.git` → `NiyaReco_love`（tmux が `.` と `:` を使えないため `_` に置き換える）
- **スレッドに別のリポジトリを紐づけたら、そのスレッドは「そのリポジトリの」セッションに入る。** 親チャンネルのセッションではありません。
  - 例: `#claude_base`（`claude_base` リポジトリ）のスレッドを `/clord-thread-init` で `qiita-article` に紐づけると、そのスレッドは `qiita-article` セッションに入ります。
  - 紐づけ方は `/clord-thread-init`、または `/clord repo:<URL>`。
- **1 スレッド = 1 ウィンドウ = 1 Claude Code セッション。** ウィンドウ名は `w1`, `w2`, … です。
- **リポジトリを紐づけていないチャンネル**のスレッドは、既定の `clord` セッションに入ります。

### 境界

- **同じリポジトリに紐づいたチャンネルが複数あると、1つのセッションを共有します。** チャンネルとセッションは 1 対 1 では**ありません**。
  - 例: 2つのチャンネルが同じ `c-lord` リポジトリに紐づいていれば、どちらのスレッドも `c-lord` セッションのウィンドウになります。
- **同じ理由で、1つのセッションの中に別々のチャンネルのスレッドが混ざることがあります。** セッション名だけでは「どのチャンネルの作業か」は分かりません。
- **1つのチャンネルのスレッドが、複数のセッションに散ることがあります。** スレッドごとに別のリポジトリを紐づけた場合です。
- **ウィンドウ番号が一意なのは「セッションの中」までです。** 別々のセッションに `w5` が同時に存在しえます。同じチャンネルのスレッド一覧に `W5` が2つ並ぶことがあるのはこのためです（→ [thread-name.md](./thread-name.md)）。
- **旧形式のウィンドウ名 `work1`, `work2`, … も読めます。** 過去に作られたウィンドウはこの形のまま残ります。新しく作るものは `w1` 形式です。

### 移動が起きるとき（いつ寄るのか）

- **スレッドの紐づけを後から変えると、そのウィンドウは新しいセッションへ「引っ越し」ます。** 新しく作り直すのではなく移動するので、**会話も画面の履歴もそのまま**ついてきます。
- **引っ越しが起きるのは「そのスレッドで次にウィンドウが必要になったとき」だけです。** 具体的には、そのスレッドのターンが始まり、**紐づけから決まったセッションにそのスレッドのウィンドウがまだ無い**とき。そこで初めて、他のセッションにある同じスレッドのウィンドウを探して移してきます。
  - **起動時に一括では寄せません。** 定期的に見回るループもありません。
  - **すでに正しいセッションに居るスレッドでは何も起きません。** ターンのたびに動かしたりはしません。
  - なので、**紐づけを変えた直後はまだ古いセッションにいます。** そのスレッドを次に使うまで、古い場所に残ります。触らないスレッドは、いつまでも古い場所のままです。
- **これは意図した動き（遅延移行）であって、直すべき不具合ではありません。** 2026-09-02 に本番で実測して確認しました（#617）:

  | スレッド | 紐づけ | ターン後の実際のウィンドウ |
  |---|---|---|
  | `1543774766115196999` | `openclaw-ops` | `openclaw-ops:w1` ✅ |
  | `1538758307433676821` | `openclaw-ops` | `openclaw-ops:w2` ✅ |

  どちらも `#claude_base`（親チャンネルは `claude_base` リポジトリ）のスレッドですが、ターンを回した時点で**親チャンネル側ではなく紐づいたリポジトリ側**のセッションに入りました。

- **引っ越せないことがあります。** 移す相手は、古いウィンドウに残っている目印（`@thread_id`、無ければ作業ディレクトリのパス）で探します。tmux サーバの再起動などで目印が失われ、作業ディレクトリも消えているウィンドウは見つけられないので、新しいウィンドウが作られ、**古いほうは持ち主のいない残骸として残ります**。この残骸の回収は #677 で扱います。

### エラー時

- セッションが tmux 側に無ければ、その名前で新しく作ります。
- 引っ越しに失敗した場合、元のウィンドウはそのまま残ります（二重に Claude が立つことは避けます）。

## バグの例

- `/clord-status` が案内した `tmux attach -t …` を**そのまま打っても辿り着けない**（存在しないセッション名やウィンドウ名を案内している）→ #616
- スレッドに別リポジトリを紐づけて**ターンを回した**のに、ウィンドウが**親チャンネルのセッションに居座り続ける**（一度も触っていないスレッドが古い場所にあるのは上のとおり仕様。#617 で実測したときは、この不具合は起きていませんでした）
- ドキュメントが「1 チャンネル = 1 セッション」だと書いている（実態と違う）→ #615

## この決め方を選んだ理由（2026-08-31, yousan の判断）

**まとめ方 = リポジトリごと／名前 = リポジトリ名**で確定しました。

- **リポジトリ名は打ちやすく、変わりにくい。** attach で手打ちする名前なので、これが効きます。
- **C-lord の本来の使い方は「1つのリポジトリ・案件に対して、セッションをたくさん立てて並行で回す」こと**（[理念 A](../PHILOSOPHY.md)）。リポジトリ単位でまとまる方がその使い方に沿います。
- **チャンネルと違うリポジトリをスレッドに紐づけるのは例外的な使い方。** 例外はスレッド名にリポジトリ名を出すなど、別の手段で見分けられるようにします（#618）。

### 検討して選ばなかった案（記録）

決めることは2つあり、独立して選べます。**① 1つのセッションに何を入れるか**と、**② それを何と呼ぶか**です。

#### ① まとめ方

| 案 | 長所 | 短所 | 判定 |
|---|---|---|---|
| A. チャンネルごと | 「そのチャンネルのスレッドはそのセッションにある」で必ず当たる。`/clord-status` はチャンネル単位なので案内と実体がそろう | attach してもウィンドウごとのリポジトリが分からない（#427 の元の不満）。多くのリポジトリを扱うチャンネルはウィンドウが増える | 却下 |
| **B. リポジトリごと** | 同じリポジトリの作業が1画面に集まる。**「1つのリポジトリにセッションをたくさん立てる」という本来の使い方に合う** | 1チャンネルが複数セッションに散る。別チャンネルのスレッドが混ざる。紐づけを覚えていないとどこにいるか分からない | **採用** |
| C. スレッドごとに1セッション | 迷いようがない | セッションが何十個にもなり `tmux ls` が読めない | 却下 |
| D. 全部1セッション | attach 先が常に1つ | ウィンドウが数百になり、チャンネルの区切りが消える | 却下 |

#### ② 名前

| 案 | 長所 | 短所 | 判定 |
|---|---|---|---|
| **あ. リポジトリ名** | 短くて打ちやすい。中身が想像できる。めったに変わらない | チャンネルと 1 対 1 にならない。リポジトリ未紐付けのチャンネルは全部 `clord` に落ちる | **採用** |
| い. Discord のチャンネル名 | Discord で見ている名前がそのまま出るので、地図のズレが原理的に起きない | **改名される**と既存ウィンドウとつながらなくなる。同名チャンネルがカテゴリ違いで作れて衝突する。**絵文字や日本語やスペース**が入り `tmux attach -t 📚絵本屋` は手で打てない。ふわっとした名前だと中身のリポジトリが分からない。Discord 側の権限を持つ人が外から名前を変えられる | 却下 |
| う. チャンネル ID | 絶対に衝突せず絶対に変わらない | `tmux attach -t 1504670029923352597` は人間には打てない | 却下 |
| え. リポジトリ名 + 衝突時だけ番号 | 1 対 1 を保てる | どちらに番号が付いたか覚えられず、「先に作った者勝ち」で不安定になる | 却下 |

**「打ちやすさ」と「Discord と 1 対 1」は両立しません**（リポジトリ名は打てるが 1 対 1 でない、チャンネル名は 1 対 1 だが打てない）。打ちやすさと本来の使い方を優先しました。

### 承知の上で残した不便

- 同じリポジトリに紐づく複数チャンネルが1つのセッションを共有する
- 1つのセッションに別チャンネルのスレッドが混ざり、セッション名からは持ち主が分からない
- 「このスレッドはどのセッションか」が Discord 側から分からない → #618 で補う
