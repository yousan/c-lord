# あるべき動き: 止まったセッションを、メッセージ1通で復元できるか

> これは「あるべき動き」。理念 [`docs/PHILOSOPHY.md`](../PHILOSOPHY.md) の下位。迷ったら理念に照らす。

## これは何か

スレッドの tmux ウィンドウが消えたとき、c-lord は `/tmux-screenshot` や `/resync` で
**「このスレッドにメッセージを送れば自動で復元し、続きから再開します」** と案内することがあります。

この spec が決めるのは 2 つ、そして**その 2 つが必ず一致すること**です:

1. その案内を出してよいのはどんなときか
2. 案内どおりにメッセージを送ったとき、実際に何が起きるか

**案内する側と受け取る側が別々に条件を持つと、必ずズレます。** 実際 #538 では、案内は
「送れば復元します」と言い切る一方、受け取る側は `sessions` にレコードが無いスレッドの
メッセージを**返信もログも無しに捨てて**いました。利用者は案内どおりに送って無視され、
次に何をすればいいのか分からない状態に置かれました。だから両者は**同じ 1 つの判定**から
文言と受理条件を導きます（`c_lord/session_resume.py`）。

## 3 つの状態

スレッドは、利用者から見て次の 3 つのどれかです。

| スレッドの状態 | メッセージを送ると | 止まっているときの案内 |
|---|---|---|
| **動く**（記録があり、終了していない） | **実行される。** ペインが落ちていれば、これまでの会話ごと自動で復元してから実行（`--continue`, #270 / #464） | 「メッセージを送れば**自動で復元**し、続きから再開します」 |
| **終了**（`[終了]` / `/close-workspace`, #512） | **実行されない。** 「▶️ 再開する」ボタン付きの案内が出る（押すと、いま送ったメッセージがそのまま走る） | 「メッセージを送ると**「▶️ 再開する」ボタンが出ます**」 |
| **記録が無い**（untracked） | **実行されない。復元もできない。** 「このスレッドには復元できるセッションがありません」＋次の一手が出る | 「メッセージを送っても**復元できません**」＋次の一手 |

「記録が無い」は、`/workspace-delete` した後・DB を作り直した後・別ホストで作られたスレッドを
見ている、などで起きます。**c-lord から見て、そのスレッドは初めて見るスレッドです。**

## あるべき動き（利用者から見て）

### 正常時

- **案内は、その時点で本当に起きることだけを言う。** 上の表の 3 行は、案内の文言と実際の
  動きが 1 対 1 で対応する。「復元します」と言われたなら復元されるし、復元できないなら
  そう言われる。
- **記録が無いスレッドに送ったメッセージは、黙って捨てられない。** 必ず次の 3 つが起きる:
  1. **ログに 1 行残る**（`thread=<id>` で grep できる）。「送ったのに何も起きない」を後から追える。
  2. **送ったメッセージに ⚠️ が付く。** 「見えてはいるが、実行していない」と一目で分かる。
  3. **スレッドに案内が出る**: 「このスレッドには復元できるセッションがありません」
     「いま送ったメッセージは Claude に届いていません」＋**次の一手**。
- **次の一手は具体的なコマンドで示す。** `/clord <やること>` でこのスレッドを新しく始められる
  （前の会話は引き継がない）。リポジトリ未設定と言われたら `/clord-thread-init repo:<URL>`
  の後にもう一度 `/clord`。

### 境界

- **同じスレッドに続けて送っても、長い案内文が毎回は出ない。** 案内は 1 スレッドにつき 1 回
  （bot の再起動でリセット）。ただし **⚠️ は毎回付く**ので、2 通目以降も「無視された」には
  ならない。
- **自分に関係ないチャンネルでは黙る。** 1 つのサーバーに複数の c-lord が居ることがあるため、
  案内を出すのは「このチャンネル（`DISCORD_CHANNEL_ID`）」か、`/clord-init` /
  `/clord-thread-init` でリポジトリが紐づいたチャンネルのスレッドだけ。それ以外では
  **ログだけ残して何も投稿しない**（全部の bot が同じ警告を並べない）。
- **立ち上がったばかりのスレッドには「記録がありません」と言わない。** `/clord` で作られた直後の
  スレッドは、Claude が最初のセッション ID を出すまで記録を持たない。その最中に追加のメッセージを
  送っても「復元できるセッションがありません」とは案内されない（記録はまさに今作られている最中で、
  そう言うのは事実に反する）。この窓では案内もリアクションも出さず、ログにだけ残す。
- **復元できる＝「記録がある」。** ディスクに transcript が残っていても、記録が無ければ
  「復元できる」とは言わない。記録をディスクから作り直すのは別の機能であり、ここで
  「たぶんできます」と言うのは #538 と同じ嘘になる。

### エラー時

- **案内やリアクションの投稿に失敗しても、他は止まらない。** どちらが落ちても**ログの 1 行は
  必ず残る**（そこだけは失敗しない順序で行う）。
- **記録を読めなかったとき**（DB エラー）は、案内は「復元できる」側の文言に倒す。記録がある
  スレッドは送れば実際に動くので、利用者を動く可能性の高い方へ送る。

## バグの例（こうなっていたらバグ）

- 「メッセージを送れば自動で復元します」と案内されて送ったのに、**返信もリアクションもログも
  出ない**（#538 そのもの）。
- 記録が無いスレッドに送ったのに、**ログに 1 行も出ない**（原因を追えない）。
- 終了済み（`[終了]`）のスレッドで「メッセージを送れば自動で復元します」と案内される
  （実際に出るのは再開ボタン）。
- 記録が無いスレッドで、案内は出るのに**次に何をすればいいか書いていない**。
- 同じスレッドに 5 回送ったら、同じ長い案内が 5 回並ぶ。
- **案内の文言と、実際に受け付ける条件が別々の場所に書かれている**（また必ずズレる）。

## 関連コマンド

| コマンド | 何をするか |
|---|---|
| `/tmux-screenshot` / `/resync` | 止まっていたら、この spec の案内を出す |
| `/clord <やること>` | 記録の無いスレッドで、新しくセッションを始める |
| `/clord-thread-init repo:<URL>` | そのスレッドにリポジトリを紐づける |
| `/reopen-workspace` | 終了したスレッドを再開する（[session-close.md](./session-close.md)） |

## 根拠

- #270 / #464 — 落ちたペインの `--continue` 自動復元と、その告知。この spec の「動く」行。
- #464 ②-2 — 止まったセッションで `/tmux-screenshot` / `/resync` が行き止まりにならないよう
  復元導線を案内するようにした。ただし**復元できるかは確認していなかった**。
- #512 — 「終了」を `closed_at` として記録。この spec の「終了」行（[session-close.md](./session-close.md)）。
- #522 — 1 サーバーに複数 c-lord が居るとき、関係ないチャンネルで喋らない。
- #538 — 案内と受理条件のズレを 1 つの判定に統合し、記録の無いスレッドを黙って捨てるのをやめた。
