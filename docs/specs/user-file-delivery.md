# あるべき動き: Claude が渡すファイル（SendUserFile）

> これは「あるべき動き」。理念 [`docs/PHILOSOPHY.md`](../PHILOSOPHY.md) の下位。迷ったら理念に照らす。

## これは何か

Claude が作ったもの（スクリーンショット・PNG・PDF・生成した HTML やレポート）を、
**利用者の手元にファイルとして渡す**話です。逆向き（Discord → Claude）は [attachments.md](./attachments.md) が担当します。

Claude Code ハーネスには `SendUserFile` というツールがあり、Claude はこれを呼んでファイルを渡します。
ツールは `1 file delivered to user.` を返しますが、**その「user」はハーネス側の配送チャンネルであって Discord ではありません**。
C-lord がそれを Discord スレッドへ橋渡ししない限り、**ファイルはどこにも届きません**。

## あるべき動き（利用者から見て）

### 正常時

- **Claude が「このファイルを渡します」と言ったら、そのファイルがスレッドに添付されて届く。**
- **ファイル名は Claude が付けた実名のまま**届く（`progress.txt` のような固定名にはならない）。
  `02-same-image-detail-loss.png` は `02-same-image-detail-loss.png` として届く。
- **説明文（caption）があれば、ファイルと同じメッセージの本文として付く。** 無ければ添付だけが届く。
- **ファイルは独立した1メッセージで届く。** 最終回答に相乗りしない。
  そのため「下に貼ります」と書いた文章 → ファイル → 最終回答、という**書いた順のまま**並ぶ。
- **11個以上渡しても全部届く。** Discord の1メッセージ10添付の上限は c-lord が分割して吸収する。
- **プッシュ通知は鳴らさない。** ターンの最終回答が鳴らすので、二重に鳴らさない。

### 境界

- **1メッセージあたりの個数** — 10個まで。超えた分は次のメッセージに回す（**捨てない**）。
- **1ファイルのサイズ** — 既定 25 MB まで。`CLORD_USER_FILE_MAX_BYTES` で変えられる。
  実際の上限は Discord のブースト段階（未ブーストなら 10 MB）で決まるので、
  この既定を通っても Discord に拒否されることはある。そのときも**告げる**。
- **サブエージェントが呼んだ場合も届く。** 「利用者に渡す」という意味は呼び出し元によって変わらない。
- **同じ呼び出しを二度読んでも二度は届かない。** transcript が書き換わっても重複投稿しない。

### エラー時

- **渡せなかったファイルは、必ずスレッドに名前と理由が出る。**
  「⚠️ 次のファイルは添付できませんでした: `foo.png` — ファイルが見つかりません」のように、
  **どのファイルが・なぜ**渡らなかったかが分かる。この警告だけはプッシュを鳴らす
  （利用者は来ないファイルを待っているので、気づけないと意味がない）。
- **黙って捨てない。** これが一番やってはいけないこと。
- **1つ失敗しても他は届く。** Discord は1メッセージを丸ごと拒否するので、
  拒否されたら1個ずつ送り直し、悪い1個が残りの9個を道連れにしないようにする。
- **説明文だけは残す。** 1個も添付できなかったときでも caption は投稿する
  （警告だけが浮くと、何の話だったのか分からなくなるため）。

## なぜこの形か

### なぜ最終回答に相乗りさせないか

1. **10添付の枠を奪い合わない** — 最終回答には `progress.txt` とテーブル PNG (#683) が既に乗る。
   同じメッセージに載せると、どれかが押し出される。
2. **順序が壊れない** — Claude は「下に貼ります」と**書いてから**ツールを呼ぶ。
   最終回答に付けると、紹介文より後に来るはずの画像が、文章より下の別位置に出る。
3. **ターンが途中で落ちても届く** — 最終回答を待って抱えていると、
   最終回答前に落ちたターンでは渡したはずのファイルごと消える。

### なぜ「Claude に作法を教える」方式にしないか

marker を本文に書かせる / sidecar ファイルを置かせる、といった方式は
**毎セッション作法を注入する必要があり、Claude が忘れれば黙って落ちます**（#491 と同じ失敗モード）。
`SendUserFile` は標準ツールなので、Claude は何も知らなくても普通に呼ぶだけで届きます。

### なぜ c-lord が投稿するか

Discord に書くのはミラー1本、という #71 の単一 writer 原則があるためです。
Claude 自身に POST させると、書き手が2つになって順序と重複の責任が分散します。

## バグの例

- **#233**: `SendUserFile` の `tool_use` をミラーが素通りさせていた。ホスト全体で **29件**が
  1件も届かないまま、ツールは毎回 `1 file delivered to user.` を返していた。
  利用者から見ると「送ったと言われたのに無い」、セッションから見ると「送れた」。
  誤診断の末に HTML ソースを本文へ丸ごと貼る、という筋の悪い回避に走った実例もある。
  jsonl ミラーが既定になって（#492）以降ずっとこの状態だった。

## 設定

| 環境変数 | 既定 | 意味 |
|---|---|---|
| `CLORD_SEND_USER_FILE` | `1` | `0` で機能ごと無効化（何も投稿しない） |
| `CLORD_USER_FILE_MAX_BYTES` | `26214400` (25 MB) | 1ファイルの上限。超えたものは送らずに告げる |

Zero-Config 原則により、**パッケージを更新するだけで有効**になります。利用者側の配線は要りません。
