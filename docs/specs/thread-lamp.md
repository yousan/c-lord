# あるべき動き: 状態ランプ 🟢 / 🟡

> これは「あるべき動き」。理念 [`docs/PHILOSOPHY.md`](../PHILOSOPHY.md) の下位。迷ったら理念に照らす。

## これは何か

利用者は、いま開いているセッションの状態を **ランプ**（色つきの丸）で一目で判断できます。

- **🟢 = いま動いている（running）** — Claude が考え中・作業中。待っていればそのうち返ってくる。
- **🟡 = 自分の番（waiting）** — Claude は返事を終えて止まっている。次の指示を出すのは利用者。
- **🔴 = エラー（error）** / **⚪ = 終了（dead）**。

なぜ要るか: C-lord の核は「複数のセッションを開いたまま並行して進める」こと（[理念 A](../PHILOSOPHY.md#a-切れないどこからでも複数を並行して進められるこれが核)）。
何本も開いていると、どれが動いていてどれが待ちかを一覧で見分けられないと回せません。ランプはその見分けを一目で済ませるためのものです。

## ランプは2層ある（#246）

| 層 | どこに出るか | 速さ | 既定 | 役割 |
|----|------------|------|------|------|
| **ターンのランプ（本命）** | **送った自分のメッセージへの絵文字リアクション** 🟢/🟡 | **即時**（送信に追従） | **常時オン** | 「いま動いてる/自分の番」をリアルタイムに示す |
| **スレッド名のランプ（サイドバー）** | スレッド名の先頭 `🟢 W3 │ <topic>` | ゆっくり（ポーリング、最大60秒・混雑時はさらに遅延しうる） | **オフ（#329）** | スレッド一覧での**ざっくりした**現状表示（オプトイン） |

**なぜ分けたか**: Discord の**スレッド名変更は「約10分に2回」という厳しいレート制限**がある。毎ターン 🟢/🟡 をスレッド名に書き込むと枠を即使い切り、429 でランプが固着し、本当に必要なメッセージ配信まで巻き添えで遅延・脱落した（#241 / #236 の回帰）。
リアクションの add/remove は**別のレート制限バケット**で即時・高頻度に耐えるため、リアルタイムのランプはリアクションが担う。スレッド名ランプは枠の許す範囲でゆっくり追従する**結果整合**の表示に降格した。

**さらにスレッド名ランプは既定オフ（#329）**: サイドバー表示に降格してもなお、ポーリングと初回命名でスレッド名 rename を消費する。並行スレッドが多いサーバーではこれだけでもレート制限に当たるため、スレッド名ランプは**オプトイン**にした。本命の**ターンのランプ（リアクション）は常時オン**なので、既定でもリアルタイムの状態把握は失われない。

### スレッド名ランプの有効化（オプトイン）

| 設定 | 既定 | 意味 |
|------|------|------|
| `CLORD_THREAD_LAMP` | `0`（オフ） | `1`/`true`/`yes`/`on` でスレッド名ランプを有効化（🟢🟡🔴⚪ を表示・rename する） |
| `CLORD_THREAD_STATE_SYNC` | `1` | ≤60秒ごとにスレッド名ランプを補正するポーリング。**`CLORD_THREAD_LAMP` がオンのときだけ動く** |
| `CLORD_THREAD_STATE_SYNC_INTERVAL` | `60` | 上記ポーリングの間隔（秒） |

コンストラクタ引数 `ClaudeChatCog(..., thread_lamp=True/False)` でも切り替えられ、こちらが環境変数より優先される（既定 `None` = 環境変数に従う、ゼロコンフィグ後方互換）。

## あるべき動き（利用者から見て）

「ランプ」は原則 **ターンのランプ（リアクション）** を指す。これがリアルタイムの真実で、**常時オン**。

### 正常時

- **メッセージを送ると、ほぼ即座に 🟢 になる。** 送った自分のメッセージに 🟢 リアクションが付く。Claude が動き出した時点で緑。レート制限の影響を受けない。
- **返信が完了すると、🟡 に変わる。** Claude が最終返信を出して止まったら、同じリアクションが 🟡 になる。利用者は「自分の番だ」と分かる。
- 作業中（考え中・ツール実行中）は **🟢 のまま**。ツールごとに絵文字が変わったりはしない（ツールの詳細はスレッド内の tool-use embed が示す）。

#### 境界

- **とても短いターン**（Claude がすぐ返す）でも、いったん 🟢 になってから 🟡 に変わる。緑を飛ばして黄のまま、にはしない。
- **同じスレッドへ続けて送ったとき** — 2通目には 2通目のメッセージへ 🟢 が付き、その返信が終わったら 🟡。1往復ごとに、その回のメッセージ上で緑→黄を繰り返す（前のメッセージの黄はそのまま残ってよい）。
- **bot が再起動した後** — ターンのランプ（リアクション）は実態に追従する。スレッド名ランプを有効にしている場合は、再起動をまたいでも止まっているスレッドは 🟡、動いているスレッドは 🟢 と、ポーリングで実態に収束する。

#### エラー時

- **Claude が失敗した・途中で死んだとき** — リアクションは緑のまま固まらず、❌（エラー）/ ⚠️（ハングの疑い）へ移る。利用者が「終わったのか止まったのか分からない」状態に置き去りにされない。
- **ランプの更新自体に失敗したとき**（Discord 側の一時的な不調など）— 本体の処理（Claude の応答）は止めない。ランプは見やすさのための飾りであって、応答経路を巻き添えにしない。

### スレッド名ランプ（サイドバー）について

- **既定では付かない（#329）。** 既定のスレッド名は `W3 │ <topic>` のように**トピック名のみ**で、先頭の状態色 🟢🟡 は出ない。turn の開始・終了でスレッドが rename されないので、レート制限に当たらない。何のスレッドかはトピック名で分かる。
- **`CLORD_THREAD_LAMP=1` で有効化したとき**、スレッド一覧での `🟢/🟡` は**ざっくりした**現状で、混雑時は実態から数十秒〜数分ずれることがある（レート制限を踏まない範囲でゆっくり追従するため）。**リアルタイムの正は、その回のメッセージのリアクション**。
- スレッド名ランプが遅れて見えても、それ自体はバグではない（設計上の結果整合）。固着して**永久に**戻らない場合のみ不具合。

## バグの例（こうなっていたらバグ）

- **処理中なのにメッセージのリアクションが 🟡 のまま。** Claude が動いている最中にリアクションが黄＝「自分の番」に見えるのは誤り。利用者が二重に指示してしまう。
- **送信してもメッセージに 🟢 が付かない。** 動き出しているのにリアクションが無い/前のままは誤り。緑は送信に追従して即つくべき。
- **返信が終わったのにメッセージのリアクションが 🟢 のまま残る。** 止まっているのに「動いている」に見えるのは誤り。完了したら黄に変わるべき。
- **スレッド名ランプの 429 でメッセージ配信まで遅延・脱落する。** ランプ（飾り）の都合で本体（応答）を巻き添えにするのは誤り（#241 の症状）。これを避けるためスレッド名ランプは既定オフ（#329）。
- **既定（`CLORD_THREAD_LAMP` 未設定）なのにスレッド名へ状態色が付く / turn ごとにスレッドが rename される。** 既定でスレッド名ランプを出さないと決めた以上、状態遷移で名前が変わってはいけない。
- **既定なのにトピック名すら付かない。** 状態色は消すが、何のスレッドかを示すトピック名は残すべき。

## 根拠

- #236 — ランプの 🟡→🟢 が最大60秒遅延した不具合の記録。これをイベント駆動の**スレッド名リネーム**で直そうとした（#240）。
- #241 / #246 — その**スレッド名リネーム**が Discord の「約10分2回」レート制限に抵触し、429 でランプ固着＋メッセージ配信遅延を招いた。リアルタイムのランプを**リアクション**に移し、スレッド名ランプは結果整合のサイドバー表示に降格した。
- #329 — サイドバー表示でもスレッド名 rename のレート制限コストが残るため、スレッド名ランプを**オプション化し既定オフ**にした（本命のリアクションランプは常時オンのまま）。
- 理念 [A（切れない・どこからでも・複数を並行）](../PHILOSOPHY.md#a-切れないどこからでも複数を並行して進められるこれが核) と [B（結果が判断できる形で見える）](../PHILOSOPHY.md#b-リモートで結果から判断するには判断できる形で結果が見えないといけないa-の必須条件) — 何本も並行する利用者が、状態を即判断できることが前提。ランプはその判断材料。
