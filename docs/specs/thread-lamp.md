# あるべき動き: スレッド名のランプ 🟢 / 🟡（既定オフ・オプトイン）

> これは「あるべき動き」。理念 [`docs/PHILOSOPHY.md`](../PHILOSOPHY.md) の下位。迷ったら理念に照らす。

## これは何か

Discord のスレッド名の先頭に、状態を表す**ランプ**（色つきの丸）を付けられます。
利用者は、スレッド一覧をぱっと見るだけで「いまどれが動いていて、どれが自分の返事待ちか」を判断できます。

- **🟢 = いま動いている（running）** — Claude が考え中・作業中。待っていればそのうち返ってくる。
- **🟡 = 自分の番（waiting）** — Claude は返事を終えて止まっている。次の指示を出すのは利用者。
- **🔴 = エラー（error）** / **⚪ = 終了（dead）**。

なぜ要るか: C-lord の核は「複数のセッションを開いたまま並行して進める」こと（[理念 A](../PHILOSOPHY.md#a-切れないどこからでも複数を並行して進められるこれが核)）。
何本も開いていると、どれが動いていてどれが待ちかを一覧で見分けられないと回せません。ランプはその見分けを一目で済ませるためのものです。

## 既定はオフ（#329）

**ランプは既定で無効**です。理由はレート制限。状態が変わるたびに Discord の**スレッド rename API**（`thread.edit(name=...)`）を呼ぶ必要があり、Discord はスレッド名の変更を **10分あたり約2回**しか許しません。並行スレッドが多いサーバーでは、ランプの塗り替えだけでこの上限を使い切り、429（レート制限）に当たります。

便益（一覧での状態把握）よりレート制限のコストが上回る環境があるため、**オプトイン**にしています。

### 有効化のしかた

| 設定 | 既定 | 意味 |
|------|------|------|
| `CLORD_THREAD_LAMP` | `0`（オフ） | `1`/`true`/`yes`/`on` でランプを有効化（🟢🟡🔴⚪ を表示・rename する） |
| `CLORD_THREAD_STATE_SYNC` | `1` | ≤60秒ごとにペインを見てランプを補正するポーリング。**`CLORD_THREAD_LAMP` がオンのときだけ動く** |
| `CLORD_THREAD_STATE_SYNC_INTERVAL` | `60` | 上記ポーリングの間隔（秒） |

コンストラクタ引数 `ClaudeChatCog(..., thread_lamp=True/False)` でも切り替えられ、こちらが環境変数より優先されます（既定 `None` = 環境変数に従う、ゼロコンフィグ後方互換）。

## あるべき動き（利用者から見て）

### 既定（`CLORD_THREAD_LAMP` 未設定）

- **スレッド名に状態色（🟢🟡🔴⚪）は付かない。** turn の開始・終了でスレッドが rename されず、レート制限に当たらない。
- **トピック名は従来どおり付く。** 例: `W3 │ 認証まわりのリファクタ`（先頭の状態絵文字なし）。何のスレッドかは一覧で分かる。
- **ユーザーメッセージのリアクション絵文字（🧠🛠️✅❌）は無効化しない** — これはランプ（スレッド名）とは別系統（`StatusManager`）で、レート制限の主因ではないため従来どおり動く。

### 有効時（`CLORD_THREAD_LAMP=1`）

以下は**ランプを有効化したときの**あるべき動き。

- **メッセージを送ると、ほぼ即座に 🟢 になる。** Claude が動き出した時点で緑。利用者は「受け取って動き始めた」とすぐ分かる。
  - 「ほぼ即座」とは、ポーリングの周期（最大60秒）を待たずに、という意味。受信してすぐ緑になるべき。
- **返信が完了すると、🟡 に戻る。** Claude が最終返信を出して止まったら黄。利用者は「自分の番だ」と分かる。
- 短いやり取りでも自然に見える。受信で緑 → 返信完了で黄、の順に切り替わる。

#### 境界（有効時）

- **とても短いターン**（Claude がすぐ返す）でも、いったん 🟢 になってから 🟡 に戻る。緑を飛ばして黄のまま、にはしない。
- **同じスレッドへ続けて送ったとき** — 2通目を受信したらまた 🟢 に戻り、その返信が終わったらまた 🟡。1往復ごとに緑→黄を繰り返す。
- **bot が再起動した後** — 再起動をまたいでも、止まっているスレッドは 🟡、動いているスレッドは 🟢 と、実態に合った色に保たれる。

#### エラー時（有効時）

- **Claude が失敗した・途中で死んだとき** — ランプは緑のまま固まらず、エラー/停止を表す状態へ移る。利用者が「終わったのか止まったのか分からない」状態に置き去りにされない。
- **ランプの更新自体に失敗したとき**（Discord 側の一時的な不調など）— 本体の処理（Claude の応答）は止めない。ランプは見やすさのための飾りであって、応答経路を巻き添えにしない。

## バグの例（こうなっていたらバグ）

- **既定（オフ）なのに turn ごとにスレッドが rename される。** 状態色を出さないと決めた以上、状態遷移で名前が変わってはいけない（レート制限回避の意味が消える）。
- **既定（オフ）なのにトピック名すら付かない。** 状態色は消すが、何のスレッドかを示すトピック名は残すべき。
- 以下は**有効時**のバグ:
  - **処理中なのに 🟡 のまま固着する。** 利用者が「返事待ちだ」と勘違いして二重に指示してしまう（#236 の症状）。
  - **受信してから緑になるまで何十秒も待たされる**（#236 / #240）。
  - **返信が終わったのに 🟢 のまま残る。**

## 根拠

- #236 — ランプの 🟡→🟢 が最大60秒遅延した不具合の記録。
- #240 — それを直した PR。受信した瞬間に 🟢、返信完了の瞬間に 🟡 へ、イベント駆動で切り替えるようにした。
- #277 — 再起動時に全スレッドを一斉 rename して Discord の rename レート制限を飽和させた問題。ランプが rename レート制限と隣り合わせであることを示す。
- #329 — 上記レート制限コストを踏まえ、ランプを**オプション化し既定オフ**にした（この仕様）。
- 理念 [A（切れない・どこからでも・複数を並行）](../PHILOSOPHY.md#a-切れないどこからでも複数を並行して進められるこれが核) と [B（結果が判断できる形で見える）](../PHILOSOPHY.md#b-リモートで結果から判断するには判断できる形で結果が見えないといけないa-の必須条件) — 何本も並行する利用者が一覧で状態を即判断できることが前提。ランプはその判断材料だが、レート制限を払ってまで常時オンにはしない。
