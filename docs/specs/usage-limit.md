# あるべき動き: 利用上限（クォータ）に当たったとき

> これは「あるべき動き」。理念 [`docs/PHILOSOPHY.md`](../PHILOSOPHY.md) の下位。迷ったら理念に照らす。

## これは何か

Claude のプラン上限（週次 / セッション（5時間枠）/ Opus・Sonnet 別枠 / 追加クレジット）に当たると、Claude は**依頼に答えず、上限の文言を返します**。

c-lord はそれを**上限到達として認識し、回復時刻つきでスレッドに出します**。「もう一度送ってください」とは言いません — 回復するまで、何度送っても同じ結果になるからです。

## あるべき動き

### 正常時 — 上限に当たったターン

スレッドにはこの 2 つが出ます。

**1. embed**

```
⏳ Claude の利用上限に達しました
Claude が weekly limit に達したため、このターンは実行されていません。
Aug 29, 4pm (Asia/Tokyo) に回復します。

回復するまでは、同じ内容を送り直しても同じ結果になります。

できること:
• 回復時刻まで待つ
• /model で上限に余裕のあるモデルに切り替える（Opus/Sonnet は上限枠が別）
• /clord-attach (または tmux) でペインの表示を直接確認する
```

**2. ターン終了の呼び出し**（[turn-end-notification.md](./turn-end-notification.md) の一種）

```
⏳ Claude の weekly limit（上限）に達したため、このターンは実行されていません。Aug 29, 4pm (Asia/Tokyo) に回復します。それまでは送り直しても同じ結果になります。 @依頼者
```

- **`🟡 Claude has finished` とは言わない。** 何も終わっていないため
- **`⚠️ 応答がありませんでした — もう一度送るか…` とも言わない。** 送り直しても通らないため（嘘の案内になる）
- **呼び出しは行う。** 利用者は待っているので、黙って放置するほうが悪い
- **回復時刻は Claude が表示した文字列をそのまま出す**（`Aug 29, 4pm (Asia/Tokyo)`）。c-lord 側で時刻を再計算しない — 利用者が一番必要としている 1 つの事実について、自信満々に間違えるのが最悪だから

### Claude が出す「どうしますか」メニューの扱い — **待つ以外は選ばない**

Claude Code 2.1.252 は、上限に当たると文言だけでなく選択メニューを開きます。

```
   What do you want to do?

   ❯ 1. Stop and wait for limit to reset
     2. Switch to usage credits
     3. Switch to Team plan
```

- c-lord は **「待つ」の選択肢だけを選びます**（上の例では 1）。メニューを開いたままにすると、**次にスレッドへ送ったメッセージが入力欄ではなくメニューに入って**しまうため、閉じる必要があります
- **2 / 3 は選びません。** どちらも課金の設定を変えるもので、利用者に代わって c-lord が決めてよい種類の判断ではありません
- 選択肢は**番号ではなく名前で探します**。並び順が変わったときに番号で選ぶと、「待つ」のつもりで Team プランを買うことになるため
- 「待つ」に当たる選択肢が**見つからないときは、何も押しません**。メニューが開いたまま残るのは人が直せますが、頼まれていないプラン変更は取り消せません

### 上限中に新しく送られたターンの扱い — **警告のみ（拒否もキューもしない）**

回復時刻までの間も、**新しいメッセージは今までどおり受け付けます**。ただし上限が続いていれば、そのターンも**即座に**上限として報告されます（待たされません）。

なぜ「拒否」でも「キュー」でもないか:

- **拒否しない**: 上限は c-lord の知らないところで解ける（プランのアップグレード、クレジット追加、`/model` での枠の切り替え、単に回復時刻の到来）。c-lord が回復時刻を覚えて門前払いすると、**もう通るはずの依頼を通さなくなる**。上限枠はモデルごとに別なので、「Opus の上限」を理由に Sonnet の依頼まで止めるのは明確に誤り
- **キューしない**: 黙って溜めると、利用者からは「送ったのに何も起きない」に見える。それは #585 の「黙って嘘をつく」に戻る。回復時刻を出して待ってもらうほうが、利用者が自分で判断できる
- **警告のみで足りる**: 検知はペインを見るだけなので、上限中のターンは 1 秒ほどで上限として返る。空振りのコストが小さい

### 境界

- **回復時刻が無いことがある。** API が `resetsAt` を返さなかったときは、Claude 自身も時刻を出しません。そのときは「回復時刻は報告されませんでした」と書き、**時刻をでっち上げない**
- **上限の種類は Claude が出した名前をそのまま使う**（`weekly limit` / `session limit` / `Opus limit` / `Sonnet limit` / `usage limit` / `org's monthly usage limit`）。翻訳や言い換えで別の枠と混同させない
- **「残り◯%」は上限ではない。** `You've used 79% of your weekly limit` / `Approaching weekly limit` / `You're close to your usage limit` は**警告**で、Claude は普通に応答します。これを上限として扱ってはいけません（元気なセッションを止めることになる）

### エラー時

- 上限の文言が Claude 自身の**回答の中に引用**されているだけのときは、上限として扱いません（このリポジトリのスレッドはまさにこの話題を扱うので、実際に起きます）。判定は「そのターンがまだ 1 文字も回答していない」ことを条件にします
- 上限を検知したターンは、待たずにその場で終わります。上限は最終回答であって、待てば変わるものではないため
- 「どうしますか」メニューの選択肢が想定と違って「待つ」が見つからないときは、メニューを開いたまま上限として報告します（勝手に課金の選択肢を押さない）

## バグの例

- 上限に当たったのに `⚠️ 応答がありませんでした — もう一度送るか、tmux ペインを確認してください` と出る（**#631 の元の症状**。利用者が同じ依頼を 3 回送った）
- 上限に当たったのに `🟡 Claude has finished` と出る（終わっていない）
- 回復時刻が出ない、または c-lord が勝手に計算した時刻が出る
- `You've used 91% of your weekly limit`（警告）でターンが止まる
- 上限を検知してから報告までに、猶予時間（2 分）ぶん待たされる
- 上限のメニューが開いたまま残り、次に送ったメッセージがメニューに吸い込まれる
- 上限のメニューで「Switch to usage credits」「Switch to Team plan」が選ばれる（頼んでいない課金変更）
- 前のターンで上限に当たったスレッドが、回復後の新しいターンでも上限扱いになって動かない

## 根拠

- #631 — 週次上限に当たっても検知せず「もう一度送ってください」と案内し続けた。実測: 2026-08-28 09:01 JST、スレッド 1515873566166483074
- #585 — 「黙って嘘をつく」クラス。案内が嘘なら、その案内は次から読まれなくなる
- 文言の一覧は Claude Code CLI 本体（2.1.252）のメッセージ生成関数から抽出。`"You've hit your ${label}${suffix}"` / `suffix = " · resets ${when}"`
