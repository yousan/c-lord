# あるべき動き: テキストコマンドの担当と認可

> これは「あるべき動き」。理念 [`docs/PHILOSOPHY.md`](../PHILOSOPHY.md) の下位。迷ったら理念に照らす。

## これは何か

c-lord のスラッシュコマンドには、`!` 始まり（と `@bot` メンション）で叩ける**テキストの双子**があります（`!clord` / `!workspace-stop` / `!skill` …）。webhook から POST できるので、CI/CD・E2E・他のエージェントからの自動化はここを通ります。

この双子には、スラッシュには無い 2 つの問いが付いてきます。

| 問い | 何を決めるか |
|---|---|
| **担当** | 同じサーバーに c-lord が何台も居るとき、**どの1台が**応じるか |
| **認可** | webhook / bot / 人間のうち、**誰が**そのコマンドを叩いてよいか |

スラッシュコマンドにこの問いは無い。Discord が**1つのアプリにだけ**ルーティングし、返事は ephemeral（本人にしか見えない）だからです。テキストコマンドは**読めるインスタンス全部に配信される**ので、c-lord 側で決めるしかありません。

## あるべき動き（利用者から見て）

### 担当 — 応じるのは1台だけ

- **そのチャンネル / スレッドを担当している 1 インスタンスだけがコマンドを実行する。**
- **担当外のインスタンスは黙る。** エラーも警告も出さない。担当インスタンスの返事に別の bot が被せるのは、利用者から見て「どれが本物か分からない」状態そのものだからです。
- **これは特定のコマンドの話ではなく、テキストコマンド全部に効きます。** 今あるものにも、これから足すものにも。

「担当している」とは、そのインスタンスが**その場所を自分のものだと示す記録を持っている**ことです:

1. `DISCORD_CHANNEL_ID` に設定されたチャンネル（スレッドなら親チャンネル）である、または
2. `/clord-init` / `/clord-thread-init` でそのチャンネル / スレッドが自分に紐づいている、または
3. 自分の `sessions` テーブルにそのスレッドの行がある（＝自分が立てたスレッド。あとでチャンネルの紐づけが外れても自分のもの）

どれにも当たらなければ**担当ではない**ので黙ります。DM は例外で、常に担当です（DM はその bot にしか届かないので、譲る相手が居ない）。

**紐づけの照会が失敗したとき（DB が応答しない等）は、担当だと名乗らない。** 一時的な不具合で傍観者が本番のスレッドを触りに行くのが、この仕組みが防ぎたいことそのものだからです。

#### ここだけ操作が変わります

**まっさらなチャンネル**（`DISCORD_CHANNEL_ID` でもなく、まだ誰にも紐づいていない）は、上の定義では**どのインスタンスの担当でもありません**。そこで**チャンネルに直接**打ったテキストコマンド（`!clord-status` / `!tmux-list` など）は、どの bot も黙ります。**スレッドの中**なら、そのスレッドの `sessions` 行を持っているインスタンスが担当なので従来どおり動きます（普段使いはこちら）。チャンネル直打ちが要るときは**スラッシュコマンド**を使ってください — ephemeral なので同居インスタンスがあっても混ざりません。

とくに `!clord-init` は影響が分かりやすいので明示しておきます:

- ❌ `!clord-init <repo>` でそのチャンネルを初めてバインドすることは**できません**（全台が黙ります）
- ✅ **`/clord-init`（スラッシュ）を使ってください。** Discord が1つのアプリにだけ届けるので、どの bot にバインドするかが曖昧になりません
- ✅ すでに自分に紐づいているチャンネルなら `!clord-init` で**貼り替え**られます（担当内なので動きます）

これは意図した動きです。まっさらなチャンネルで `!clord-init` が全台に届くということは、**居合わせた bot 全部が勝手にそのチャンネルを自分のものとして登録する**ということで、それは事故です。

### 認可 — webhook は人間用 allowlist を通らない

- **webhook から送ったテキストコマンドは、`DISCORD_OWNER_ID` を設定していても通る。** webhook URL を持っていること自体が認可だからです。
- **`CLORD_TRUSTED_BOT_IDS` に登録した bot も通る。** 人間と同じ扱い。
- **それ以外の bot は拒否される。**
- **人間は従来どおり allowlist（owner / role）で判定される。**
- **スラッシュコマンドは常に人間用 allowlist のまま。** メッセージが無く、webhook から来ようがないからです。

この規則は `!clord` / `!attach` / `!skill` / `!clord-init` / `!clord-thread-init` で同一です。

## なぜこうなっているか

2026-08-27、完了したワークスペース2本を畳むためチャンネル webhook に `!workspace-stop` を1回投げたところ、**staging bot 3台が本番のスレッドで実行**し、「🛑 停止しました」が1スレッドあたり3〜4個並びました（#596）。

原因は、テキストコマンドが「担当か」を**ほぼどのコマンドも聞いていなかった**ことです。#522 でチャンネル単位のガードは入りましたが、`!clord` の「紐づけが解決できなかったとき」の枝だけに効くもので、他の 20 本以上には効いていませんでした。

同じ根から反対向きに出ていたのが #507 / #508 で、**認可**の方を人間用 allowlist で判定していたために webhook が必ず弾かれていました。

判定を**コマンドごとに書く**限り、次に足すコマンドで必ずまた忘れます。だから両方の規則を [`c_lord/command_gate.py`](../../c_lord/command_gate.py) に1つずつ置き、**担当判定は `ClaudeDiscordBot.process_commands` の一箇所**で全テキストコマンドに掛けています（コマンド側に書き足す場所はありません）。
