# あるべき動き: スレッド名（トピック＋Issue/PR番号）

> **#574 で改名**: 操作名は「終了」→「**停止**」、コマンドは `/close-workspace` → `/workspace-stop`、`/reopen-workspace` → `/workspace-start`、スレッド名のマーカーは `[終了]` → `[停止]` になりました。**旧コマンド名はエイリアスとして動き続けます**（利用者側の変更は不要）。既存スレッドに残る `[終了]` も引き続き正しく解釈されます。理由: 7日で自動発火するようになるため、何も失っていないのに「終了」と言われると誤解を招くから。詳細は [workspace-vocabulary.md](workspace-vocabulary.md)。

> これは「あるべき動き」。理念 [`docs/PHILOSOPHY.md`](../PHILOSOPHY.md) の下位。迷ったら理念に照らす。

## これは何か

各スレッドの名前は、**何のスレッドか**を一覧で見分けるための見出しです。形はこうです:

```
<状態絵文字> W<番号> │ #<当初のIssue番号> <トピック> →#<いま作業中の番号>
<状態絵文字> <リポジトリ名>:W<番号> │ #<当初のIssue番号> <トピック>   ← 別リポジトリに紐づけたスレッド（#618）
[終了] #<当初のIssue番号> <トピック>        ← 終了済み（#512）
```

例: `🟢 W3 │ #404 認証リファクタ` / 既定（状態絵文字オフ）では `W3 │ #404 認証リファクタ` / 途中で別の Issue に移ったら `W131 │ #540 メモリ →#588` / 終了後は `[終了] #404 認証リファクタ` / 別リポジトリに紐づけたスレッドは `qiita-article:W1 │ #598 Qiita記事執筆`

- **W<番号>** — そのスレッドの tmux ウィンドウ番号（`w{N}`。過去に作られたものは旧形式の `work{N}`）。
  **番号が一意なのは tmux セッションの中まで**で、チャンネルの中ではありません。セッションはリポジトリごとに分かれるので、
  同じチャンネルのスレッド一覧に `W5` が2つ並ぶことがあります（→ [tmux-layout.md](./tmux-layout.md)）。
- **`<リポジトリ名>:`** — そのスレッドが**親チャンネルとは違うリポジトリ**に紐づいているときだけ、W番号の前に付きます（#618）。
  付いた形は `tmux attach -t` にそのまま渡せる形（`qiita-article:W1` → `qiita-article:w1`）なので、名前を見れば attach 先が分かります。
  チャンネルと同じリポジトリのスレッド（大多数）には**付きません** — 既存のスレッド名は変わりません。
- **#<当初のIssue番号>** — そのスレッドが**何のために立ったか**を示す番号（#593）。一度決まったら**二度と変わらない**。サイドバーでそのスレッドを見つけるための手掛かりはこれ。
- **→#<いま作業中の番号>** — いま作業している Issue/PR の番号（#414）。**当初と違うときだけ**出る。ブランチを切り替えれば追従する。
- **トピック** — 最初のメッセージから作る短い日本語の要約（≤20字）。
- **状態絵文字** — ランプ。既定オフ。詳細は [thread-lamp.md](./thread-lamp.md)。
- **`[終了]`** — `/close-workspace` で**意図的に終了した**セッションの印（#512）。付いている間は `W<番号> │` とランプ絵文字は出ない。

なぜ要るか: C-lord の核は「複数のセッションを並行して進める」こと（[理念 A](../PHILOSOPHY.md#a-切れないどこからでも複数を並行して進められるこれが核)）。
一覧で「どの Issue/PR の作業か」を一目で見分けられることが、並行運用の前提になります。番号は揺れない事実なので、要約より頼りになります。

## あるべき動き（利用者から見て）

### 正常時

- **トピックは最初に一度だけ決まり、その後は勝手に変わらない（#414）。** 初回メッセージから要約を作って名前に入れ、以後の会話で**自動的に付け替えたりしない**。
  - 以前は会話の途中で「作業が変わった」と判定して自動リネームしていた（#121）が、精度が悪く意図しないリネームが多かったため、**既定でオフ**にした。
- **作業中の Issue/PR 番号が `#<n>` で出る。** 番号は次の順で自動的に決まる:
  1. **git ブランチ名**（例 `fix/404-...` → `#404`）。Claude がブランチを切り替えれば追従する（最優先）。
  2. ブランチに番号が無く、まだ番号が未確定なら、**スレッド最初のメッセージ**に書かれた `#NNN` や GitHub の issue/pull URL から拾う。
- **一度ついた番号は安定する。** 再起動しても保持され、勝手に消えない。**新しいブランチ番号が出たときだけ**差し替わる。
- **当初の番号は、作業が別の Issue に移っても名前から消えない（#593）。** そのスレッドで初めて番号が分かったときの番号を「当初の番号」として固定し、名前の先頭に出し続ける。作業が別の番号に移ったら `→#<いまの番号>` を後ろに足す。
  - 例: `#540` の相談から始まったスレッドで、担当が派生の `#588` を起票して `feature/588-...` に切り替えると `W131 │ #540 メモリ →#588` になる。**`#540` は消えない。**
  - なぜ: スレッド名は**サイドバーでそのスレッドを見分ける唯一の手掛かり**。作業中の番号だけを出していると、依頼した本人が自分の依頼を見失う（実際に起きた — 「540 って何だっけ？」）。「いま何をしているか」と「そもそも何のスレッドか」は別の役割なので、名前も別の枠に分けている。
  - **当初の番号が無いスレッド**（雑談から始まったもの）は、今までどおり番号なしで表示される。無い番号を作らない。
- **手で名前を変えたら、それが優先される（#95）。** Discord 上でスレッド名を手動で変更すると、c-lord は以後その名前を自動で上書きしない。
- **終了したら名前の先頭が `[終了]` になる（#512）。** `/close-workspace` を実行すると、スレッド名は `[終了] #404 認証リファクタ` になる。
  - `W<番号> │` は**消える**。番号が指していた tmux ウィンドウは、まさにいま `/close-workspace` が消したものなので、残すと存在しない窓を指し続けることになる。
  - ランプ絵文字も出ない。ランプは「生きているペインの様子」を表す印であり、終了後にはその対象が無い。
  - **`[終了]` は「終了」であって「dead」ではない。** ⚪ dead は「いま tmux ウィンドウが無い」だけ（bot 再起動・tmux サーバ死などを含む）で、次のメッセージで黙って復元される（#270）。`[終了]` は利用者が自分で終わらせた状態で、次のメッセージは**実行されず**再開の案内が出る。詳細は [session-close.md](./session-close.md)。
  - **60 秒ごとのサイドバー同期（#120）は `[終了]` を剥がさない。** 終了スレッドは同期ループから見ると「ウィンドウ無し = dead」なので、印を持たない名前に描き直してしまうのを防いでいる。
- **再開すると `[終了]` は消える。** `/reopen-workspace` か案内の「▶️ 再開する」ボタンで `[終了] #404 認証リファクタ` → `#404 認証リファクタ` に戻る。`W<番号> │` は**次のメッセージで実際にウィンドウが立ってから**戻る（存在しない番号を先に書かないため）。

### 境界

- **番号が分からないとき** — `#<n>` を省いて従来どおり `W<番号> │ <トピック>` になる（番号トークンは付かない）。
- **名前が長いとき** — 全体は **45 字**上限（Discord 自体の上限は 100 字。読みやすさのために c-lord 側で短く抑えている）。はみ出すときは、まず **`→#<いまの番号>` を落とす**（#593 — 当初の番号とトピックが先）。次に**トピックを切り詰める**（当初の番号は残す）。それでも入らない極端な場合は、まず **`<リポジトリ名>:`** を、次に `W<番号> │` を、次に `#<番号>` を落としてでもトピックを残す（#618）。つまり通常はリポジトリ名が残り、代わりにトピックが切り詰められる — 「どのセッションにいるか」が分からないと attach 先を間違えるため、トピックの長さより優先する。
  - `→#<いまの番号>` は**足せるときだけ足す**。トピックを削ってまで入れることはない。
  - 上限が 30 字だった頃は、既存 195 本のうち 46 本（24%）が既に切り詰められていた。そこに `→#NNN`（6 字）を足すと「当初を残す」ために「何の作業か」が読めなくなるため、#593 で 45 字に引き上げた。
- **終了マークが付いていて長いとき** — `[終了] ` はランプ絵文字と `W<番号> │` を**置き換える**（足すのではない）ので、実質の追加コストは 2 字程度。それでも上限を超えるときは、通常どおりトピックから切り詰める（`[終了]` は落とさない — それ自体が状態だから）。
- **会話の途中で別の番号に言及しても、タイトルは乗っ取られない。** 既に番号が確定しているスレッドで本文に `#999` と書いても、`#999` には変わらない（誤爆防止。番号を変えたいときはブランチを切り替えるか手動リネーム）。
- **ブランチが `main`/`master` など番号を含まないとき** — そこからは番号を取らない（`v2-api` の `2` や `step-2` の `2` のような付随的な数字も拾わない）。

### エラー時

- **番号の検出に失敗しても本体は止めない。** git ブランチが読めない・リポジトリでない等は無視し、番号なしで命名を続ける。命名は見やすさのための飾りであって、応答経路を巻き添えにしない。

## バグの例（こうなっていたらバグ）

- **既定なのに、会話の途中でトピックが勝手に書き換わる。** #414 で自動付け替えは既定オフにした。`CLORD_THREAD_RETITLE` 未設定で付け替えが起きるのは誤り。
- **作業中の Issue/PR 番号が出ない／間違った番号が出る。** ブランチ `fix/404-...` なのに `#404` が付かない、または無関係な番号が付くのは誤り。
- **手で変えた名前を c-lord が勝手に上書きする。** 手動リネーム後に自動命名が割り込むのは誤り（#95）。
- **手動リネーム後、番号がトピック本体に二重化する**（`#404 #404 ...`）。パーサーが先頭 `#番号` を取り除けていない兆候（#414）。
- **作業が別の Issue に移ったら、当初の Issue 番号が名前から消えた。** `W131 │ #540 メモリ` が `W131 │ #588 メモリ` になるのは誤り（#593）。正しくは `W131 │ #540 メモリ →#588`。
- **手動リネーム後に `→#588` がトピック本体に取り込まれる**（`… →#588 →#588` と二重化する）。パーサーが末尾の `→#番号` を剥がせていない兆候（#593）。
- **`/close-workspace` してもスレッド名が `W3 │ …` のまま。** 終了が一覧で見分けられないのは誤り（#512）。
- **終了マークが二重になる**（`[終了] [終了] …`）。手動リネーム検出のパーサーが `[終了]` を剥がせていない兆候（#512）。
- **終了したのに、しばらくすると `[終了]` が消えている。** 60 秒ポーリングの同期ループが終了状態を見ずに名前を描き直している兆候（#512）。

## 設定

| 設定 | 既定 | 意味 |
|------|------|------|
| `CLORD_THREAD_RETITLE` | `0`（オフ） | `1`/`true`/`yes`/`on` で会話途中のトピック自動付け替え（#121）を再有効化 |

コンストラクタ引数 `ClaudeChatCog(..., thread_retitle=True/False)` でも切り替えられ、環境変数より優先される（既定 `None` = 環境変数に従う、ゼロコンフィグ後方互換）。

## 根拠

- #95 — スレッド命名の再設計（安定トピック + 状態）。手動リネームのロックもここ。
- #121 — 会話途中のトピック自動付け替え（`maybe_retitle`）。本 spec で**既定オフ**に変更。
- #414 — 自動付け替えを既定オフにし、代わりに **Issue/PR 番号**をブランチ/本文から自動検出して名前に表示する変更。
- #512 — `/close-workspace` した終了状態を `[終了]` として名前に出し、終了済みスレッドへの投稿をブロックして再開導線を出す変更。
- #618 — `W<番号>` が一意なのは tmux セッション内までで、同じチャンネルに `W5` が2つ並ぶ状態が実在した（`W5 │ 2017.l2tp.org` と `W5 │ monitoring`）。サイドバーの `W1` を見て親チャンネルのセッションを attach しても辿り着けない（実体は `qiita-article:w1`）ため、**別リポジトリのときだけ**左端にリポジトリ名を出すことにした。右端は名前が長いと切れる＝必要な場面でこそ消えるので、左端に置いている。
- #593 — 「いま作業中の番号」と「そもそも何のスレッドか」を 1 枠に載せていたため、ブランチを切り替えると当初の番号が消えていた。`sessions.origin_issue_ref` を追加して当初を固定し、名前の上限を 30 → 45 字に引き上げた。W 番号が付け替わる件は #595 で扱う。
- 状態絵文字（ランプ）については [thread-lamp.md](./thread-lamp.md) を参照。終了時の挙動全体は [session-close.md](./session-close.md) を参照。
