# あるべき動き: ターン末尾の 📊 フッタ

> これは「あるべき動き」。理念 [`docs/PHILOSOPHY.md`](../PHILOSOPHY.md) の下位。迷ったら理念に照らす。

## これは何か

ターンが終わると、スレッドの末尾に小さな1行が出ます。

```
-# 📊 7% context (69k/1.0M) · fable-5 · xhigh · CLI 2.1.260 · c-lord v1.4.183-bd80c47e-20260908 · $5.7500
```

**このターンが「どういう条件で走ったか」を1行で残すためのもの**です。あとから
「なぜこの挙動になったのか」を切り分けるとき、最初に見る値がここに並びます。

## あるべき動き

### 正常時

出す項目と、その**出どころ**:

| 項目 | 何を言っているか | 出どころ |
|---|---|---|
| `7% context (69k/1.0M)` | いまコンテキスト窓をどれだけ使っているか | そのターンの transcript の `usage`（分子）／`/context` の実測または既定値（分母） |
| `fable-5` | 実際に答えたモデル | そのターンの transcript の `model` |
| `xhigh` | そのターンの effort | c-lord がその実行に渡した値 |
| `CLI 2.1.260` | **そのターンを動かした Claude Code の版数** | **そのターンの transcript の `version`** |
| `c-lord v1.4.183-bd80c47e-20260908` | **そのターンを動かした c-lord 自身の版数** | **プロセス起動時に固定した `runtime_version()`** |
| `$5.7500` | セッションの累計コスト | ペインの statusline |

**どの項目も「そのターンの実際の値」であること。** フッタは切り分けの出発点なので、
ここに出る値は**観測値であって、記憶していた値であってはいけません**。

**版数はとくにそうです（#693）。** Claude Code は自分で自動更新します。bot の起動時に
`claude --version` を1回だけ叩いて憶えておくと、bot が何日も動き続ける本番では**必ず**
実体とズレます。だから版数は、**このフッタが既に読んでいる transcript の行**から取ります
— 追加のプロセスを起こさず（`claude --version` を毎ターン叩かない）、かつ常にそのターンの
実体と一致します。

**c-lord 自身の版数は逆に、起動時に固定します（#722）。** 理由は同じ「そのターンの実体を出す」です。
c-lord の**走っているコードは import した時点で決まっている**ので、`git pull` / `uv tool upgrade`
してもプロセスを再起動するまで挙動は変わりません。ここで毎ターン `git describe` を読み直すと、
**古いまま走っているビルドが「いま pull した新しい commit です」と名乗る**ことになります
— #722 がまさに止めたかった向きの嘘です。だから `runtime_version()` は最初の1回で確定し、
プロセスが生きている間は変わりません（版数が変わるのは再起動＝走るコードが変わるときだけ）。
副作用としてターンごとの git サブプロセスもゼロになります。

**2つの版数は並べて出します。** 「どの Claude Code が / どの c-lord で動いたターンか」は
切り分けで必ずセットで要るので、`CLI …` の隣に `c-lord …` を置いて1目で読めるようにします。

### 境界

- **セッションの途中で CLI が更新された** — 出すのは**新しいほうの版数**。フッタは
  「そのターン」を説明するものなので、そのターンを書いた版数が正しい
- **そのターンの transcript に版数が無い**（古い CLI など） — `CLI …` の**項目ごと消す**。
  `None` も、以前どこかで見た値も出さない。**知らないことは黙る**
- **c-lord の版数が解決できない**（git も配布メタデータも無い環境） — `c-lord …` の
  **項目ごと消す**。`c-lord unknown` とは出さない（同じく「知らないことは黙る」）
- 各項目は `context_footer.<項目>` 設定で個別に消せる。消した項目は行から消える
- **利用者の次の発言に割り込まれて終わったターンでは、フッタ自体を出さない**（#583）。
  そのターンは終わりに到達していないし、フッタは `⚡ Interrupted…` の直後＝**割り込んだ
  メッセージの上**に出るので、新しい発言への返事のように見える。置き換えたターンが自分の分を出す

### エラー時

- transcript が読めない・`usage` が無いターンでは、**フッタ自体を出さない**（ゼロや推測を出さない）
- フッタの送信に失敗しても、**ターンの結果には影響しない**（飾りは本体を壊さない —
  [turn-resilience.md](./turn-resilience.md)）

## バグの例

- **`c-lord vX` がプロセス再起動なしに変わる** → **バグ**（#722）。走っているコードは
  変わっていないのに版数だけ新しくなる＝古いビルドが新しいと名乗っている
- **`CLI x.y.z` が bot 起動時の版数のまま固定される** → **バグ**（#693）。
  2026-09-04 に本番が2日間 `2.1.258` を出し続け、実体は `2.1.260` だった。
  版数は切り分けで最初に見る値なので、**#684 の調査が一度逆方向に行きかけた**
- 版数が取れないときに `CLI None` と出る → **バグ**（項目ごと消すべき）
- フッタを出すためにターンごとに `claude --version` を spawn する → **バグ**
  （観測はタダで済むところから取る）
- フッタが出ないせいでターンの結果まで届かない → **バグ**（飾りが本体を壊している）
- **そのターンの最終回答より前**にフッタが出る／次のターンの頭に出る → **バグ**（#583）。
  フッタはターン終了に紐づくので、ターンが閉じないと回答から切り離されて漂う

## 根拠

- **#722** — c-lord 自身の版数がログにもフッタにも出ず、09-02 のビルドで走っていた
  インスタンスが「その機能はありません」と利用者に答えた（実際は2日前に出ていた機能）。
  気づく経路が1つも無かったので、フッタに `c-lord …` を追加した
- **#693** — 版数が bot 起動時のまま固定され、調査を誤らせた。出どころを transcript の
  `version` に変更（`claude --version` のプロセス寿命キャッシュを廃止）
- **#455** — フッタを返信に足さず独立したメッセージとして出す（progress.txt の後、🟡 の前）
- **#583** — ターンが閉じないせいでフッタが最終回答から切り離されていた。割り込みで終わった
  ターンではフッタを出さない
- **#425** — synthetic な no-op エントリを分子に採らない。版数も同じエントリから採らない
