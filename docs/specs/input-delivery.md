# あるべき動き: 送ったメッセージが Claude に届くこと

> これは「あるべき動き」。理念 [`docs/PHILOSOPHY.md`](../PHILOSOPHY.md) の下位。迷ったら理念に照らす。

## これは何か

Discord のスレッドに書いたメッセージ（本文・貼り付けたログ・添付したテキストファイル）が、
**そのまま欠けずに Claude に渡る**、という話です。

C-lord は Discord を Claude Code の入口にするためのものなので、入口で入力が消えたら他の何もかもが意味を失います。
これは [理念 A](../PHILOSOPHY.md) の前提そのもの — 送ったものが届いていない状態では、返ってきた答えが正しいかどうかすら判断できません。

## あるべき動き（利用者から見て）

### 正常時

- **送った本文は、長さに関係なく全文が Claude に届く。** 途中で切れない。先頭だけ届く、ということもない。
- **貼り付けた長いログも同じ。** 数万文字を貼っても、それが1つの発言として Claude に渡る。
- **テキスト添付の中身も同じ。** 添付を付けたメッセージは、本文と添付の中身がひとまとまりで届く。
- **1通目でも2通目以降でも同じ。** スレッドを立てた最初の発言と、その後の返信とで挙動が変わらない。
- **bot の起動・再起動の最中に送ったメッセージも届く。** 起動処理が終わるのを待つ必要はない。起動が重い日でも、投げたものが黙って消えることはない。
- **自分が送った入力が、スレッドに投稿し返されない。** Discord には既に元のメッセージがあるので、写しをもう一度出さない（ペインで人間が直接打った入力だけがミラーされる）。
- **日本語・絵文字が壊れない。** どれだけ長くても、文字が化けたり半分になったりしない。
- **URL がそのまま届く。** 本文に貼ったリンクが途中でエスケープされたり書き換えられたりしない。

### 境界

- **とても長い入力（数十 KB〜）** — 届く。内部で分割して送るかどうかは実装の都合であって、利用者から見える違いは無い。
- **長い／複数行の入力（おおむね 1000 文字以上）** — 届く。Claude Code の TUI はこの大きさの入力を「貼り付け」とみなして
  `[Pasted text #N +M lines]` に畳むが、**畳み込みが終わるのを待ってから送信する**ので、送信キーが畳み込みに吸われて
  本文が入力欄に残る、ということは起きない。
- **セッションが何百件も溜まっているとき** — 起動が長くかかること自体はあり得るが、その間もメッセージは受け取られる（受け取りと起動処理は互いを待たない）。
- **空メッセージ（添付だけ）** — 添付の中身が渡る。
- **上限を超えて渡せない添付があるとき** — 「渡せなかった」ことがスレッド上で分かる（黙って捨てない）。詳細は [attachments.md](./attachments.md)。

### エラー時

- **届かなかったときは、必ずそれと分かる。** 「送ったのに何も起きない」「空の返事が返って完了扱いになる」は起きない。
- **「送れた」と嘘をつかない。** 本文をペインに打ち込んだだけでは送信できたことにならない。c-lord は送信キーのあとに
  **入力欄を読み直して本文が消えたことを確認**し、残っていれば送信し直す。それでも送れなければ失敗として報告する
  （#560。それ以前は送信キーの終了コードだけを見ていたため、本文が入力欄に残っていても成功として扱われていた）。
- **エラー文には、何が起きたかと次にどうすればよいかが書いてある。** 内部の関数名だけを出して終わり
  （例: `Failed to send input to Claude in tmux`）にはしない。次の一手は**失敗の種類ごとに変える**:
  - **ペインが入力自体を受け付けなかった**とき → 入力サイズと `/restart-claude` で立て直せることを示す。
  - **本文は入力欄に入ったのに送信されなかった**とき → 本文が入力欄に残っている旨と、**送り直し**を先に示す。
    ここで `/restart-claude` を勧めてはいけない（入力欄の本文ごと破棄され、利用者が書いたものが失われる）。
  - **送り先の window を一意に特定できなかった**とき（同名 window が複数ある）→ 重複している window 名と、
    ホストで実状態を見る `tmux list-windows` を示す。ここで `/restart-claude` を勧めてはいけない
    （window の中の Claude を立て直すだけなので、名前の重複は残り、打っても直らない）。詳細は
    [tmux-window-identity.md](./tmux-window-identity.md)。

## バグの例

- 20KB のマークダウンを添付したら、Claude 側の履歴にその発言自体が残っておらず、Discord には `❌ Failed to send input to Claude in tmux` とだけ出て 3 秒で「完了」になった（#527 の実例。原因は tmux が 1 コマンド ~16KB を超える送信を `command too long` で拒否していたこと）
- 長い入力の 1 行目だけが Claude に届き、残りが別の発言として次々に投げられる
- スレッド1通目に書いた内容が、そのままスレッドにもう一度投稿し返される（#530 で解消）
- 添付が上限を超えていたのに何の表示も無く、Claude が「そんなファイルは無い」と答える（#528 で解消。[attachments.md](./attachments.md)）
- スレッド1通目に貼った URL だけが壊れていて Claude が取得に失敗する（#529 で解消）
- 1200 文字ほどの複数行メッセージが `[Pasted text #2 +5 lines]` の形で入力欄に残ったまま 20 分以上放置され、Claude は 1 トークンも動かず、エラーも出なかった（#560 で解消。TUI の貼り付け畳み込みの最中に送信キーが届き、送信ではなく貼り付けの一部として吸われていた。c-lord 側は送信キーの終了コードが 0 なので成功と誤認していた）
- bot を再起動した直後にスレッドへ投げたメッセージが、返事も案内も無いまま消える（#537 で解消。起動処理が Discord との接続を止めてしまい、切断中に送られたメッセージが Discord 側から二度と配信されないため。「遅い」ではなく「届いていない」）

## 根拠

- #527 — tmux の IPC 上限 (`MAX_IMSGSIZE` = 16384) により 16KB 超の入力が丸ごと消えていた。送信を分割し、失敗時の文言を利用者が動ける形に変えた。
- #528 — 添付の無言ドロップを廃止し、添付をディスク上の実ファイルとして渡すようにした。
- #529 — 1通目のプロンプトが zsh の行編集を通っていたため `url-quote-magic` に URL を壊されていた。プロンプトはファイル経由で渡すようにした。
- #530 — cold start のプロンプトに c-lord 由来マーカーが付かず、ミラーが入力を Discord に返していた。
- #537 — 起動時の同期 jsonl 読みがイベントループを止め、Discord ゲートウェイの heartbeat 切れ→再接続ループを招いていた。切断中のメッセージは復帰後も配信されないため、無言で消えていた。重い読み取りを別スレッドに逃がし、終了済みセッションは起動対象から外した。
- #560 — `send-keys -l` の直後に送った Enter が TUI の貼り付け畳み込みに吸われ、本文が入力欄に残っていた。畳み込みを待ってから送信し、**送信後に入力欄を読み直して確認**するようにした。確認できなければ再送し、それでも駄目なら失敗として報告する。
- #649 — 同時に立てた2スレッドが同名の tmux window を2枚作り、`session:名前` のターゲットが曖昧になっていた。生きているペインに対して「ペインが落ちています → `/restart-claude`」と案内していたため、指示どおり操作しても直らず、2スレッドが丸1日死んだままになった。ターゲットを一意な `window_id` に変え、この失敗には専用の文言を出すようにした（[tmux-window-identity.md](./tmux-window-identity.md)）。
- 理念: 入口で入力が消えることは「リモートで結果から判断する」の前提を壊す。
