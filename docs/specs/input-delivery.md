# あるべき動き: 送ったメッセージが Claude に届くこと

> これは「あるべき動き」。理念 [`docs/PHILOSOPHY.md`](../PHILOSOPHY.md) の下位。迷ったら理念に照らす。

## これは何か

Discord のスレッドに書いたメッセージ（本文・貼り付けたログ・添付したテキストファイル）が、
**そのまま欠けずに Claude に渡る**、という話です。

C-lord は Discord を Claude Code の入口にするためのものなので、入口で入力が消えたら他の何もかもが意味を失います。
これは [理念 A](../PHILOSOPHY.md) の前提そのもの — 送ったものが届いていない状態では、返ってきた答えが正しいかどうかすら判断できません。

## あるべき動き（利用者から見て）

### 正常時

- **送った本文は、長さに関係なく全文が Claude に届く。** 途中で切れない。先頭だけ届く、ということもない。
- **貼り付けた長いログも同じ。** 数万文字を貼っても、それが1つの発言として Claude に渡る。
- **テキスト添付の中身も同じ。** 添付を付けたメッセージは、本文と添付の中身がひとまとまりで届く。
- **1通目でも2通目以降でも同じ。** スレッドを立てた最初の発言と、その後の返信とで挙動が変わらない。
- **自分が送った入力が、スレッドに投稿し返されない。** Discord には既に元のメッセージがあるので、写しをもう一度出さない（ペインで人間が直接打った入力だけがミラーされる）。
- **日本語・絵文字が壊れない。** どれだけ長くても、文字が化けたり半分になったりしない。

### 境界

- **とても長い入力（数十 KB〜）** — 届く。内部で分割して送るかどうかは実装の都合であって、利用者から見える違いは無い。
- **空メッセージ（添付だけ）** — 添付の中身が渡る。
- **上限を超えて渡せない添付があるとき** — 「渡せなかった」ことがスレッド上で分かる（黙って捨てない）。詳細は [attachments.md](./attachments.md)。

### エラー時

- **届かなかったときは、必ずそれと分かる。** 「送ったのに何も起きない」「空の返事が返って完了扱いになる」は起きない。
- **エラー文には、何が起きたかと次にどうすればよいかが書いてある。** 入力サイズと、`/restart-claude` で立て直せることを示す。
  内部の関数名だけを出して終わり（例: `Failed to send input to Claude in tmux`）にはしない。

## バグの例

- 20KB のマークダウンを添付したら、Claude 側の履歴にその発言自体が残っておらず、Discord には `❌ Failed to send input to Claude in tmux` とだけ出て 3 秒で「完了」になった（#527 の実例。原因は tmux が 1 コマンド ~16KB を超える送信を `command too long` で拒否していたこと）
- 長い入力の 1 行目だけが Claude に届き、残りが別の発言として次々に投げられる
- スレッド1通目に書いた内容が、そのままスレッドにもう一度投稿し返される（#530 で解消）
- 添付が上限を超えていたのに何の表示も無く、Claude が「そんなファイルは無い」と答える（#528 で解消。[attachments.md](./attachments.md)）
- スレッド1通目に貼った画像の URL だけが壊れていて Claude が取得に失敗する（#529）

## 根拠

- #527 — tmux の IPC 上限 (`MAX_IMSGSIZE` = 16384) により 16KB 超の入力が丸ごと消えていた。送信を分割し、失敗時の文言を利用者が動ける形に変えた。
- #528 — 添付の無言ドロップを廃止し、添付をディスク上の実ファイルとして渡すようにした。
- #529 — 1通目の URL が zsh の `url-quote-magic` に壊される。
- #530 — cold start のプロンプトに c-lord 由来マーカーが付かず、ミラーが入力を Discord に返していた。
- 理念: 入口で入力が消えることは「リモートで結果から判断する」の前提を壊す。
