# あるべき動き: ターン終了の呼び出し（🟡 / ⚠️）

> これは「あるべき動き」。理念 [`docs/PHILOSOPHY.md`](../PHILOSOPHY.md) の下位。迷ったら理念に照らす。

## これは何か

ターンが終わると、そのターンを頼んだ人にメンション付きのメッセージが 1 通届きます。これは**呼び出し**です — 利用者はやっていたことを中断して見に来ます。

だから**内容が事実と食い違ってはいけません**。「終わりました」と言われて見に行ったのに何も返っていなければ、その通知は次から読まれなくなります。

## あるべき動き

### 正常時 — 応答があったターン

```
🟡 Claude has finished — your reply is needed here. @依頼者
```

- 出るのは **PROCESSING → WAITING_INPUT の遷移時に 1 回だけ**
- メンションは**そのターンを頼んだ人**（スレッド作成者ではなく、そのターンの発言者）
- 人が頼んでいないターン（webhook / スケジュール実行）は `DISCORD_OWNER_ID` にフォールバック。設定が無ければメンション無しで投稿
- メンションは**文末**に置く。Discord のプッシュ通知のプレビューが「@you」ではなく本文で始まるようにするため

### 応答が 1 文字も無かったターン

```
⚠️ 応答がありませんでした — Claude がこのターンを開始しませんでした。もう一度送るか、tmux ペインを確認してください。 @依頼者
```

- **「終わりました」とは言わない。** 終わっていないため
- **呼び出しは行う。** 利用者は待っているので、黙って放置するほうが悪い
- あわせて `⚠️ 応答がありませんでした` の embed（次の一手つき）が出る

判定は「**このターンが実際に始まったか**」で行います。具体的には、生成インジケータを一度も観測しておらず、かつペインから応答テキストが一度も取れていない場合を「開始していない」とみなします。ターンが**始まって**から静かになった場合（回答が transcript mirror 経由で届いたケース）は別で、これは正常終了です（#541）。

### 境界

- ターンの開始が遅れているだけの場合に「応答がありません」と言ってはいけない。開始までには**猶予**があり、その間はターンを終わらせない。猶予は Claude が起動済みかどうかに関わらず効く（かつては冷起動時にしか効かず、温かいセッションでは 60 秒静止しただけで終了扱いになっていた）
- ホストが混んでいると起動に時間がかかる。猶予はそれを見込んだ長さにする

### エラー時

- 通知の送信に失敗しても、ターンの処理を巻き添えにしない

## バグの例

- 何も返っていないのに `🟡 Claude has finished` が飛ぶ → **バグ**（#562）
- ハングの疑い（⚠️）を出した直後に `🟡 Claude has finished` が並ぶ → **バグ**。2 つの判定が食い違っている（#473 で本文表記は削除され、⚠️ はリアクションのみになった）
- 応答があったターンで 🟡 が出ない → **バグ**
- 1 ターンで 🟡 が複数回飛ぶ → **バグ**
- ターンを頼んでいない人がメンションされる → **バグ**（#481 / #525）

## 根拠

- **#562** — 応答が無いまま「終わりました」と通知していた。yousan の直接報告:
  「僕が発言した時にいきなりメンションが飛んできて呼ばれることがある。でも全然実際の作業としては終わってないはずなのに」
- **#365** — 「新しいターンが実際に始まったか」のゲート。#562 はこのゲートを idle 経路が無視していたのが原因
- **#541** — 正常終了したターンで誤ってタイムアウトを報告していた件。判定の順序はこの spec と同じ根（ポーリング脱出後の判定）にある
- **#481 / #520 / #525** — 誰をメンションするか
- **#495** — メンションを文末に置く理由
- **#473** — `⚠️ No activity for 30s` 本文は削除済み。ハングの疑いは ⚠️ リアクションだけで示す
