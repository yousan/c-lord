# あるべき動き: 作業場所を用意できなかったとき

> これは「あるべき動き」。理念 [`docs/PHILOSOPHY.md`](../PHILOSOPHY.md) の下位。迷ったら理念に照らす。

## これは何か

スレッドで依頼すると、c-lord はまず**作業場所**を用意します — リポジトリのクローン（チェックアウト）と、
Claude を動かす tmux ウィンドウです。この spec は、その用意に**失敗したとき**に利用者に何が見えるべきかを決めます。

## あるべき動き

### 正常時

- 作業場所が用意でき、Claude が起動し、応答がスレッドに届く（この spec の出番は無い）

### エラー時

- **スレッドに ❌ と理由が出る。** 🟢 のまま黙って止まらない。依頼者にはメンションが飛ぶ（埋め込みだけでは通知が鳴らないため）
- 依頼メッセージのランプは **❌** になる（🟢 が点きっぱなしにならない）
- **クローンに失敗したとき** は、どのリポジトリか・**git 自身が出したエラー**（最後の数行）・次に確かめること（URL / ブランチ名 / ホストから届くか）が出る
- **認証が要る失敗**（private リポジトリに権限が無い、ユーザー名を聞かれた、SSH 鍵が拒否された）は、
  「**アクセスに認証が必要です**」と分かる文言で出る。GitHub は権限の無い private リポジトリを
  「存在しない」と返すので、URL の打ち間違いも同じ表示になる、とも書く
- **tmux が使えないとき**（ホストに tmux が無い等）は、tmux を確認するよう出る
- ターンはそこで終わる。**次の投稿はまた最初から用意を試みる**（直したあと送り直せば動く）
- ログには ERROR で残る（`grep "thread=<id>"` で拾える）

### 境界

- git のエラーが長いときは**最後の数行だけ**を出す（理由はたいてい最後に書かれている）
- リポジトリ URL にトークン等の認証情報が入っていても、スレッドには**出さない**（`https://***@` の部分を落とす）
- git が何も出力しなかったときも、「理由を出力しなかった」と書いて ❌ は出す

## バグの例

- クローンに失敗したのに、スレッドには何も出ず 🟢 のまま止まる（#477 の実害 — 利用者のスレッドが3ヶ月そのまま残っていた）
- 認証の失敗が「クローンに失敗しました」だけで、何をすればいいか分からない
- エラーに URL 内のトークンがそのまま出る
- `/clord` や `POST /api/spawn` で立てたスレッドだけ、途中で落ちてもログにすら残らない

## 根拠

- **#477** — clone / tmux 起動失敗がスレッドに出ず、無言 stall になっていた
- **#565** — ターンが落ちたことをログに出す（ここではスレッドにも出す）。`/clord`・`/api/spawn` 経路にもこの記録を付けた
- **#681** — 起動に失敗したターンは依頼者にメンションする
- **#621 / #629** — ウィンドウが無いときの文言（「ウィンドウがそもそも存在しない」）はそちらの spec / 実装が持つ
