# あるべき動き: フリートの tmux が落ちたとき

> これは「あるべき動き」。理念 [`docs/PHILOSOPHY.md`](../PHILOSOPHY.md) の下位。迷ったら理念に照らす。

## これは何か

1 台のホストで動く c-lord のスレッドは、**全部が 1 つの tmux サーバのウィンドウ**に入っています。
だから、そのサーバが落ちる/入れ替わると、**そのとき走っていたスレッドの Claude が一斉に止まります**。
自分のスレッドでは何も悪いことをしていなくても止まります。

この spec は、そうなったときに **止まった各スレッドに何が見えるべきか** を決めます。
（そもそも落とさないための規約は [`docs/STAGING.md` → 実機 tmux を触る検証は必ず `-L` で分離する](../STAGING.md#実機-tmux-を触る検証は必ず--l-で分離する-701)。
ここは「それでも落ちたとき」の話です。）

## あるべき動き

### 正常時

- tmux サーバが入れ替わっていない限り、**この案内は出ない**。ウィンドウを作る・スレッドが増える・
  セッションが増えるといった通常のフリートの動きは、入れ替わりとして扱われない

### 落ちたとき

- ターンの途中で tmux サーバが入れ替わったら、**そのターンを走らせていたスレッドに理由が出る**:

  > ⚠️ フリートの tmux が落ちたため中断しました

- 案内には次の3つが必ず含まれる:
  1. **このスレッドの操作が原因ではない**こと（巻き添えである、と明言する）
  2. **作業内容は残っている**こと（ワークスペース・ブランチ・コミットはディスク上に無事。消えたのはペインだけ）
  3. **次の一手** — もう一度送れば新しいペインで再開する
- 巻き添えになったスレッドが複数あれば、**その全部に**出る（1本だけに出て他が無言、は不可）
- そのターンは「終わりました」として扱わない。応答が無いのだから、
  完了の呼び出し（🟡）ではなく中断として扱う（[turn-end-notification.md](./turn-end-notification.md) と同じ規律）
- bot のログにも ERROR で残る（`tmux server changed mid-turn (<前> → <後>)`、`thread=<id>` 付き）

### 境界

- **tmux の状態が読めない**（tmux が無い / 問い合わせが失敗した）→ **何も言わない**。
  「分からない」を「落ちた」と言い換えない。無関係な tmux の不調でフリートのせいにするのは、
  原因不明のクラッシュと同じくらい人を迷わせる
- ターン開始時点でサーバが読めていなかった → 比較相手が無いので、この案内は出ない（従来どおりの診断に落ちる）。
  したがって **ターンが始まる前にすでに落ちていた**場合は、この案内ではなく従来の
  「このスレッド用の tmux ウィンドウがありません」が出る（既知の境界）
- 落ちたのが**ターンの途中か、起動中か、メッセージ送信中か**は問わない。どの段階で落ちても同じ理由が出る
  （起動中に落ちたときに「`/clord-init` でチャンネルが紐づいているか確認してください」と案内するのは**バグ** —
  設定は正常で、見に行かせる先が間違っている）
- サーバは同じままで claude だけが死んだ → **これは巻き添えではない**。従来どおり
  「Claude exited without producing a response」（＝そのスレッド固有のクラッシュ）が出る

## バグの例

- 巻き添えで死んだスレッドに `❌ Claude exited without producing a response
  (possible startup failure or crash)` としか出ない。**これはバグ** — 読んだ人は自分の作業に
  原因を探しに行き、共通原因（tmux が落ちた）には永久に辿り着けない
- 案内は出るが「ペインを見てください」と言う。**バグ** — そのペインを持っていたサーバはもう存在しない
- 通常のウィンドウ作成でこの案内が出る（誤検出）。**バグ** — 毎ターン「フリートが落ちた」と言う狼少年になる
- 落ちたのに、そのターンが「終わりました」として通知される。**バグ**（応答は無い）

## 根拠

- **#701** — 2026-09-08、1本の作業スレッドが `tmux -f /dev/null new-session …`
  （`-f` は設定を読まないだけで**分離しない**）を実行し、本番 tmux サーバが入れ替わって
  走っていた3本（#677 / #678 / W13）が 5 分以内に全滅した。3本とも
  `❌ Claude exited without producing a response` としか出ず、**巻き添えの2本には理由が伝わらなかった**。
  W13 の完成間近の成果（+372/-228・テスト通過）は、yousan が「変な状態になっている」と
  気づかなければ宙に浮いていた
- **実測 (2026-09-08、`-L` 分離リグ)** — tmux サーバの入れ替わりは2通りある。① ソケットが消えた/繋がらない
  状態で誰かが `new-session` を打つと、tmux は**そのソケットを張り替えて新サーバを立てる**（旧サーバは
  プロセスとして生き残るが到達不能な孤児になる）。② `kill-server` 等でサーバが落ちて誰も後を継がない。
  **①②のどちらでも、走っていたスレッドのペインは失われる**ので、この spec の案内は「入れ替わった」場合
  だけでなく「サーバが居なくなった」場合にも出る。なお**生きているサーバに `new-session` を打っても
  合流するだけで壊れない**（`-f /dev/null` を付けても同じ）ことも実測済み — つまり
  「誰かが `-L` を忘れた」は**引き金**ではあっても、サーバが落ちた**原因そのものとは限らない**。
  だから c-lord 側の対処は「原因を問わず、入れ替わり/消失を検出して理由を出す」形になっている
- [trust-prompt.md](./trust-prompt.md) の「あるべき動き」 — **原因が分かっているなら、
  一般化されたクラッシュ表示で済ませない**（#630 / #684）。この spec はその規律を、
  原因がスレッドの**外**にある場合へ広げたもの
- [turn-end-notification.md](./turn-end-notification.md) — 応答の無いターンを「終わりました」と言わない
