# あるべき動き: 飾りの表示が失敗してもターンは死なない

> これは「あるべき動き」。理念 [`docs/PHILOSOPHY.md`](../PHILOSOPHY.md) の下位。迷ったら理念に照らす。

## これは何か

c-lord はターンのまわりに**飾り**を出します。チャンネル上部の 📊 Session Status ダッシュボード、
`⏺ Session running` の Stop ボタン、`⏳ Waiting for a free session slot...` の順番待ち案内、
スレッド名、進捗の1行 — どれも「Claude に頼んだことを進める」ためではなく、**状況を見せるため**のものです。

この spec は、その飾りが Discord 側の都合で出せなかったときに**何が起きるべきか**を決めます。

## あるべき動き

### 正常時

- **依頼は必ず Claude に届く。** 飾りが出せたかどうかは、依頼が実行されるかに一切影響しない
- 飾りが1つ欠けても、**残りの飾りと本体（Claude の応答）はそのまま出る**

### 境界

- ダッシュボードのメッセージが消されていた／編集できない → **ターンはそのまま走る**（ダッシュボードだけが古いまま）
- Stop ボタンの案内が投稿できなかった → **ターンはそのまま走る**。この場合ボタンは出ないので、停止は `/stop` で行う
- 順番待ち案内が投稿できなかった → **順番待ちそのものは正しく行われる**（案内が出ないだけ）
- ボット停止中（Discord への接続が閉じたあと）に飾りの更新が走った → 例外は外に出ない

### エラー時

- 飾りの投稿・編集・削除の失敗は、**握りつぶす。ただしログには WARNING で残す**（黙って捨てない）
- **飾りの失敗を利用者に見せない。** 「ダッシュボードを更新できませんでした」はスレッドに出さない
  — 利用者にできることが何も無く、頼んだ仕事とは関係がないため
- 逆に、**本体（Claude の実行）の失敗は必ず見せる**。ターンが失敗したときは ❌ とエラー本文が出る

## バグの例

- **メッセージを送ったのに、応答も ❌ も何も出ず、送ったこと自体が無かったことになる**（#632 の実害）。
  飾りの更新が例外を投げてターンごと落ちると、こうなる。**これはバグ**
- ダッシュボードの更新に失敗したことを WARNING で残さず、完全に無音で捨てる。**これもバグ**（原因が追えない）
- Stop ボタンが出せなかったときに、ターンを中止して「開始できませんでした」と出す。**バグ**
  — 出せないのはボタンだけで、依頼自体は実行できる

## 根拠

- **#632** — 「処理中」ダッシュボード更新だけ例外が素通りしていて、ターンごと死んで依頼が無言で消えた。
  同じファイルの `finally` 側には既にガードがあり、**片側だけ抜けていた**
- **#91** — ボット停止時の `RuntimeError("Session is closed")` が伝播してボットがゾンビ化した
- **#423** — スレッド名付けの失敗はターンを止めない。ただし黙って捨てず WARNING で残す
- [`turn-progress.md`](./turn-progress.md) の「エラー時」 — 進捗表示という別の飾りについて、同じことを既に決めている
- CLAUDE.md の規約「Discord API 呼び出しは `contextlib.suppress` で包む / ビジネスロジックのエラーは黙って握りつぶさない」
